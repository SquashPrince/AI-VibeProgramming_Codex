# Sprite 컨벤션

## 기본 개념

Sprite는 Texture 전체나 일부 영역을 2D 이미지로 다루는 에셋이다. 원본 이미지 데이터와 사용할 영역·Pivot 등 Sprite 구성을 구분한다.
[그래픽 공통 기준](<Common Convention.md>)에 따라 실제 역할과 사용처를 확인하고 필요한 설정만 제안한다.

## 용도와 기존 구성

- UI·캐릭터·배경·애니메이션 프레임 등 용도를 확인하고 기존 이미지·Sprite·참조를 조사한다.
- 이미지 전체를 하나로 사용할지 여러 영역으로 분할할지 제안한다.
- 신규 제작·분할·기존 수정의 차이와 영향을 설명한다. 기존 분할 영역·이름 변경은 애니메이션·UI 등 사용처를 확인한다.
- 원본 이미지·분할 정보·참조를 임의 수정·삭제하지 않는다. 이름과 경로는 [구조 규칙](<../Work/Structure Convention.md>)을 따른다.

## 설정 안내와 사용자 작업

| 항목 | 의미와 제안 기준 |
|---|---|
| Sprite Mode | 하나로 사용할지 여러 Sprite로 나눌지 결정 |
| 분할 | 영역 크기·간격·여백을 확인해 자동·수동 방식을 비교 |
| Pivot | 배치·회전·크기 변화의 기준점. 발 위치·중심 등 실제 요구로 선택 |
| Pixels Per Unit | 픽셀과 월드 단위의 관계. UI의 실제 크기는 Canvas 등 별도 조건도 함께 확인 |
| Mesh Type | 사각형과 외곽선 기반 메시의 차이. 투명 영역·정점 수·사용 컴포넌트의 조건 비교 |
| Border | 9-slicing용 경계. 모서리를 유지하며 늘리는 UI 등에 필요할 때 설정 |

- 에이전트가 값·분할안·이유와 영향을 설명하고, 사용자가 에디터에서 직접 설정한다.
- 모든 항목을 매번 변경하거나 일괄 기본값으로 강제하지 않는다.
- 압축·색 공간·해상도·필터링·Alpha·Mipmap은 [Texture 컨벤션](<Texture Convention.md>)을 참조한다.

## Sprite Atlas와 포함 목록

Sprite Atlas는 여러 Sprite를 Atlas Texture로 패킹해 사용하는 기능이다. 배칭에 도움이 될 수 있지만 모든 Sprite를 하나로 묶는 규칙은 아니다.

- 실제로 함께 쓰이는 범위와 로딩·표시 수명을 확인해 구성을 제안한다. 작은 일부 때문에 큰 Atlas가 필요한 메모리·로딩 비용도 검토한다.
- 포함 목록 등록과 패킹·미리보기·실제 적용 테스트를 별도 단계로 구분한다.
- 사용자가 요청하고 승인하면 에이전트가 Atlas 포함 목록을 등록할 수 있다. 기존 Atlas 버전·파일 형식·제어 도구를 확인해 방법을 선택한다.
- 등록 전에 대상 Atlas, 추가·제거 목록, 기존 목록과의 중복, 이름·참조 충돌 및 영향 범위를 보고한다. 폴더 단위 등록이면 포함되는 범위도 확인한다.
- 기존 목록·참조는 임의 제거·교체하지 않는다. 파일 목록 반영만으로 패킹 성공을 보고하지 않는다.
- 패킹·미리보기는 자동 실행하지 않는다. 사용자가 수행하고, 에이전트는 실제 적용·품질·성능 테스트 방법을 안내한다.
- 등록에 따른 임포트 등 에디터 반응이 있을 수 있으므로 정지·지연이 없다고 보장하지 않는다. 미리보기 때문에 멈춘다는 추정은 확인된 원인과 구분한다.
- 신규 Atlas 생성·설정 변경이나 관련 `.meta`가 필요하면 [승인 규칙](<../Safety/Approval Convention.md>)에 따라 별도로 대상을 보고한다.

## 최적화 검토

| 기법 | 목적·조건과 주의점 | 검색 키워드 |
|---|---|---|
| Sprite Atlas | Texture 전환과 배칭 조건 검토. 동일 Atlas라도 Material·순서·마스크 등으로 배치가 나뉠 수 있음 | Unity Sprite Atlas batching |
| Sprite Batching | 그리기 호출과 상태 변경의 비용 검토. 사용 Renderer·UI 시스템의 조건을 구분 | Unity SpriteRenderer batching / uGUI batching |
| Overdraw | 투명 영역과 중첩의 픽셀 처리 비용 검토. 외곽선 메시가 언제나 더 빠른 것은 아님 | Unity Sprite Overdraw Tight Mesh |

Atlas Packing의 여백·회전·밀착 패킹·압축 등은 사용처와 버전의 지원 조건을 확인해 제안한다. 편집기 옵션을 임의로 켜지 않는다.
배칭 기법의 공통 개념은 [Material](<Material Convention.md>), Texture 압축은 [Texture](<Texture Convention.md>)을 참조하며 실제 적용 대상의 차이를 설명한다.
검색 자료와 대안 검토, 예상 효과·사용자 변경·전후 비교는 [성능 컨벤션](<../Safety/Performance Convention.md>)을 따른다.

## 사용자 적용 후 테스트

- 변경 전에는 기존 구성과 예상 효과만 검토하고 실제 최적화가 확인되었다고 표현하지 않는다.
- 사용자 변경 후 실제 표시 크기·정렬·회전 기준·프레임 흔들림·경계 번짐과 필요한 확대·축소 조건을 확인하도록 안내한다.
- Atlas는 사용자 패킹 후 누락·잘림·이웃 영역 번짐·마스크·9-slicing 등 관련 항목을 확인한다.
- 동일한 장면·순서·대상 수에서 메모리·렌더링 비용·배치가 나뉘는 이유와 화질을 비교한다.
- 포함 목록 등록 확인과 패킹·실제 표시·성능 확인을 각각 보고하고 미검증 항목을 남긴다.
