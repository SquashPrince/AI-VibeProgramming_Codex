# Shader 컨벤션

## 목적과 기본 개념

[그래픽 공통 기준](<Common Convention.md>)을 바탕으로 원하는 효과에 맞는 Shader 구현 방식을 선택한다.

| 용어 | 역할 |
|---|---|
| Shader | 물체의 위치·표면·색 등을 렌더링 과정에서 계산하는 프로그램 |
| Material | 사용할 Shader와 색상·Texture 등 입력 설정을 담는 에셋 |
| Texture | 이미지 또는 계산용 데이터를 담는 입력 |
| ShaderLab | Unity Shader의 프로퍼티·SubShader·Pass 등 구성을 선언하는 틀 |
| HLSL | 정점 위치·픽셀 색상 등 계산을 작성하는 코드 언어 |
| Shader Graph | 계산을 노드와 연결로 구성하는 편집 방식 |

개념을 설명할 때 현재 작업에서 각 요소가 무엇을 담당하는지 함께 안내한다.

## 구현 방식 선택

1. 원하는 시각적 결과와 적용 대상을 확인한다. 효과 정의·추가 질문은 공통 기준을 따른다.
2. 기존 Shader·Material과 Unity 기본 기능의 설정만으로 가능한지 확인한다.
3. 신규 구현이 필요하면 Shader Graph·직접 코드·혼합 방식 중 실질적인 대안을 비교한다.
4. 유지보수·사용자 조절 편의·난이도·기존 구현·학습 목적을 고려해 권장 이유를 설명하고 선택받는다.

Shader Graph나 HLSL을 일괄 기본값으로 강제하지 않는다. 학습 목적으로 HLSL을 선택하는 것도 유효한 선택으로 다룬다.
필요한 기능만 구성하고 사용하지 않을 효과나 Shader Variant를 미리 추가하지 않는다.

### 요구사항 확인 예시

표면이 지워지는 효과라면 지워지는 방향·경계 표현·그림자 처리·스크립트 제어 여부가 구현에 영향을 줄 수 있다.
이미 정해진 사항은 유지하고 실제 선택에 필요한 항목만 확인한다. 모든 효과에 이 질문 목록을 강제하지 않는다.

## 호환성과 렌더링 조건

- 설치된 Unity·URP·Shader Graph 버전과 실제 렌더러·적용 대상을 확인한다. 최신 문서와 차이가 있으면 현재 프로젝트에서 사용할 방법을 구분한다.
- 조명 반응, 불투명·투명 처리, 양면 표시, 깊이·그림자와 필요한 Pass는 요구사항에 관련된 항목만 설명한다.
- 지원하지 않는 기능이나 패키지·프로젝트 설정 변경이 필요하면 이유·대안·영향을 보고한다. 임의로 설치·변경하지 않는다.
- 기존 Shader의 프로퍼티나 렌더링 계약을 변경하기 전에 Material·코드·사용처의 영향을 확인한다.
- 노드 편집은 [Shader Graph](<Shader Graph Convention.md>), 직접 코드 작성은 [HLSL](<HLSL Convention.md>)을 따른다.

## Shader 최적화 검토

공통 설명·검증 절차는 [성능 컨벤션](<../Safety/Performance Convention.md>)을 따른다. 아래는 관련 있을 때 설명할 기법이며 일괄 적용 목록이 아니다.

| 기법·검색 키워드 | 목적과 적용 판단 | 비용·주의점 | 사용자 확인 방법 |
|---|---|---|---|
| Texture Sampling | Texture를 읽는 횟수·방식과 데이터 접근 비용 검토 | 샘플 제거로 품질·필터링이 달라질 수 있고 샘플 수만으로 비용을 단정할 수 없음 | 같은 장면에서 GPU 시간과 경계·거리별 화질 비교 |
| Overdraw | 같은 화면 영역을 여러 번 처리하는 비용 검토 | 투명 효과의 중첩·화면 점유율에 따라 영향이 달라짐 | 같은 시점에서 중첩 수를 비교하고 GPU 비용 관찰 |
| Shader Variants / Variant Stripping | 키워드 조합으로 만들어지는 프로그램과 빌드 부담 관리 | 필요한 조합을 제거하면 실제 효과가 누락될 수 있음 | 빌드 크기·시간과 필요한 효과의 대상 빌드 표시 확인 |

최적화 제안에는 프로젝트 조건, 예상 효과와 화질·기능 손실 가능성을 함께 적는다.
분기·정밀도는 HLSL 문서, SRP Batcher·GPU Instancing은 Material 문서를 참조해 중복 설명하지 않는다.

## 검증 안내

- Shader 컴파일 오류·경고, Material 연결, 실제 효과의 확인 단계를 구분한다.
- 조절값의 기본값·경계값, 필요한 조명·시점·투명도·그림자 조건을 정해 테스트하도록 안내한다.
- 사용자 에디터 작업은 변경 후 테스트하며, 에이전트가 코드 검사를 수행했더라도 실제 표시 검증으로 대신하지 않는다.
- 성능 제안은 같은 기기·장면·카메라·해상도에서 비교한다. 성능 향상을 코드 길이나 노드 수로 단정하지 않는다.
