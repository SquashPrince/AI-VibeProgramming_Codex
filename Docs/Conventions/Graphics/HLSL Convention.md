# HLSL·셰이더 코드 컨벤션

## 적용 범위

HLSL, ShaderLab 및 Shader Graph Custom Function에 연결하는 코드를 작성·수정·설명할 때 적용한다.
요구사항과 방식 선택은 [그래픽 공통](<Common Convention.md>) 및 [Shader](<Shader Convention.md>) 기준을 따른다.

## 초보자 코드 설명

- 작성 전에 필요한 코드 구역과 입력→계산→출력의 흐름을 설명한다. 셰이더 코드 작성 경험을 전제하지 않는다.
- 새로운 문법·자료형·함수는 의미와 사용 이유를 설명한다. C#과 다른 의미·실행 방식은 구분한다.
- 수식은 입력 예시·결과·화면 변화와 연결한다. 전문 용어로 바꿔 말하는 것으로 설명을 끝내지 않는다.
- 작성 후 Material 연결, 조절 항목, 적용 위치와 확인 방법을 안내한다.
- 오류는 위치·원인·수정 이유를 설명한다. 수정 코드만 다시 제공하지 않는다.

## 구조와 명명

- 역할별 구역과 데이터 흐름이 보이게 작성하고, 불필요한 축약과 과도하게 합친 계산을 피한다.
- 기존 파일·유사 구현을 먼저 확인하고 필요한 기능만 추가한다. 재사용 필요가 없는 공통 파일·함수 분리를 강제하지 않는다.
- [코드 명명](<../Code/Code Convention.md>)과 [서식](<../Code/Formatting Convention.md>)은 해당 언어에 적용 가능한 항목을 따른다. C#의 클래스·접근 제한자·생명주기·파일과 대표 타입 일치 규칙을 HLSL에 기계적으로 적용하지 않는다.
- Unity의 Pass·키워드·진입점·플랫폼 규약이나 Custom Function의 함수명 접미사 등 기술상 필요한 이름은 해당 버전 규약을 따른다.
- 프로퍼티 이름은 [Shader Graph의 프로퍼티 기준](<Shader Graph Convention.md>)을 참고하고, 기존 Material·스크립트와 연결된 식별자를 임의 변경하지 않는다.

## 상세 한국어 주석

- 초보자가 코드만 읽어도 흐름을 이해하도록 한국어 주석을 작성한다.
- 구역의 역할, 입력과 출력, 처음 등장한 문법·자료형·함수, 계산과 화면 결과의 관계를 설명한다.
- 필요한 값의 범위·단위와 판단 이유를 남긴다. 코드의 모든 줄을 문장으로 번역하지 않는다.
- 같은 파일에서 이미 설명한 개념은 반복하지 않고 현재 처리의 목적·차이만 설명한다.
- 대화에서 설명했더라도 코드 이해에 필요한 핵심 설명은 주석에 유지한다.
- 정확성·불필요한 설명 방지 등 공통 기준은 [코드 서식의 주석](<../Code/Formatting Convention.md>)을 따른다.

### 설명 예시

```hlsl
// float3는 숫자 3개를 묶는 자료형이며 여기서는 RGB 색상을 담는다.
// saturate는 강조 강도를 0~1로 제한해 두 색 사이에서만 섞이게 한다.
// lerp는 강도가 0이면 원래 색, 1이면 피격 색을 반환한다.
float3 result = lerp(baseColor, hitColor, saturate(strength));
```

위 코드는 계산 일부의 예시다. 실제 작성 시 입력값 선언과 호출·출력 위치도 함께 설명한다.
다른 구역에서 같은 함수를 쓰면 정의를 반복하는 대신 무엇을 왜 섞는지 설명한다.

## Custom Function 연계

노드 모드 선택·포트 연결은 [Shader Graph](<Shader Graph Convention.md>)에서 관리한다.
코드를 작성할 때는 함수 인자와 포트의 순서·이름·자료형·출력 방식, 정밀도와 텍스처 인자 형식을 설치 버전에서 확인한다.
File 방식의 정밀도 접미사와 중복 포함 방지 등을 설명하고, 실제로 필요한 형태만 구현한다.

## 코드 최적화 검토

| 기법·검색 키워드 | 설명과 적용 판단 | 주의점·테스트 |
|---|---|---|
| Shader Precision / half vs float | 데이터 범위와 필요한 정밀도에 따라 자료형 검토 | 하드웨어에 따라 효과가 다르므로 성능을 단정하지 않음. 좌표·그라데이션·작은 변화의 오차 확인 |
| Shader Branching | 조건에 따라 계산을 선택하는 방법 검토 | 조건을 썼다는 이유만으로 다른 계산이 실행되지 않는다고 가정하지 않음. 생성 코드·대상 GPU와 같은 장면의 시간 비교 |
| Common Subexpression | 반복 계산과 중복 데이터 처리를 점검 | 컴파일러 최적화가 있을 수 있으므로 수동 정리가 성능 개선이라고 단정하지 않음. 가독성·결과와 측정값 비교 |

텍스처 샘플링·오버드로·Variant는 [Shader](<Shader Convention.md>), 공통 설명·검색어·측정 절차는 [성능 컨벤션](<../Safety/Performance Convention.md>)을 참조한다.
제안 단계는 예상으로 보고하고 실제 적용 후의 측정과 구분한다.

## 검증과 결과

- 문법·프로퍼티·연결의 정적 확인, Unity Shader 컴파일, 실제 표시·동작·성능 측정을 구분한다.
- 사용자 테스트에는 적용 Material·대상·입력·예상 화면·오류 확인 방법을 안내한다.
- 기본값·범위 경계·필요한 조명과 시점 조건을 확인하고, 수행하지 못한 항목은 미검증으로 보고한다.
