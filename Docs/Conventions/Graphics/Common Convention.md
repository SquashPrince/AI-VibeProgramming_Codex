# 그래픽 에셋 공통 컨벤션

## 목적과 문서 역할

그래픽 작업을 처음 배우는 사용자도 효과와 구현 선택을 이해하고 직접 설정·확인할 수 있도록 지원한다.
이 문서는 다음 그래픽 작업의 공통 기준이다.

- Shader
- HLSL
- Shader Graph
- Material
- Texture
- Sprite

이미지 생성과 편집 절차는 [이미지 생성 컨벤션](<Image Generation Convention.md>)을 먼저 적용하고, 설명과 기존 에셋 검토의 공통 기준은 이 문서를 참조한다.

| 문서 | 참조 시점 |
|---|---|
| [Shader](<Shader Convention.md>) | Shader 구현 방식 선택, 렌더링 요구와 호환성 검토 |
| [HLSL](<HLSL Convention.md>) | HLSL·ShaderLab 코드 작성·설명·수정 |
| [Shader Graph](<Shader Graph Convention.md>) | 노드 안내·현황 파악·정리·프로퍼티·Sub Graph·Custom Function |
| [Material](<Material Convention.md>) | 생성 안내·공유·개별 변경·렌더링 최적화 검토 |
| [Texture](<Texture Convention.md>) | 용도·임포트·압축 설정 제안 |
| [Sprite](<Sprite Convention.md>) | 분할·Pivot·크기·Atlas 목록 관리 |
| [이미지 생성](<Image Generation Convention.md>) | 레퍼런스 분석, 방향 확정, 생성과 편집, 결과 검수 |

필요한 분야만 추가로 읽는다. 아래 예시와 각 문서의 기술 목록은 필수 생성 목록이나 선택 범위의 제한이 아니다.

## 요구사항과 환경 확인

- 원하는 외형·움직임·변화 과정과 적용 대상을 먼저 파악한다. 기존 설명·에셋·참조 자료에서 확인할 수 있는 내용은 조사하고 이미 제공된 내용은 재질문하지 않는다.
- 참조 이미지·영상이 외형 참고인지 동작 재현 대상인지 구분한다.
- [프로젝트 값](<../../Project Values.md>)과 실제 Unity·렌더 파이프라인·관련 패키지·대상 플랫폼을 확인한다. 차이가 있으면 [환경 컨벤션](<../Work/Environment Convention.md>)에 따라 보고한다.
- 기술 이름을 몰라도 자연어로 표현한 결과를 해석하고, 실제 요구를 구현 방식으로 연결한다.

## 효과 후보와 추가 질문

- 관련 효과를 제안할 때 한글·영문 이름, 쉬운 정의와 화면에서 보이는 결과를 설명한다. 검색어를 별도 문단으로 제공한다.
- 불확실한 후보는 가능성으로 표시한다. 근거 없이 특정 효과로 단정하거나 이름을 억지로 붙이지 않는다.
- 해석이 여러 가지라면 관련성이 높은 소수의 후보와 시각적 차이를 설명한다. 사용자 검색 결과의 이미지·영상도 의도 확인 자료로 활용한다.
- 아직 미확정인 시각적 차이에 따라 서로 다른 효과로 나뉘는 경우에만 `명확한 정의를 위한 추가 질문`을 표시한다.
- 이미 확인받거나 정의된 효과를 임의로 불명확하게 취급하지 않는다. 기존 답변·자료로 구분되는 내용은 재질문하지 않는다.
- 이해가 어려운 경우 현재 이해한 모습을 쉬운 말로 다시 표현하고, 남은 구분점에 대해 설명·확인을 반복한다. 확인된 사항은 유지한다.

### 효과 안내 예시

말씀하신 모습은 **디졸브(Dissolve)**일 가능성이 있습니다. 표면이 부분적으로 지워지는 효과입니다.

`Unity dissolve effect`로 검색해 보실 수 있습니다.

**명확한 정의를 위한 추가 질문**

전체가 서서히 흐려지는 모습인가요, 아니면 표면에 구멍이 생기고 퍼지면서 사라지는 모습인가요?

위 질문은 두 표현이 아직 구분되지 않았을 때의 예시다. 이미 디졸브로 확인된 요청에는 붙이지 않는다.

## 초보자 설명 기준

- 처음 사용하는 용어는 무엇이며 어디에 쓰는지 설명하고 구체적인 작업 예시와 연결한다.
- 원리, 실질적인 선택지, 장단점, 권장 이유, 작업 영향, 확인 방법 순서로 이해를 돕는다.
- HLSL·셰이더 코드의 문법과 작성법은 기초 지식을 전제하지 않는다. Shader Graph는 기본 사용 경험을 전제로 새 노드·기능·버전 차이를 중심으로 설명한다.
- 이미 이해한 내용은 불필요하게 반복하지 않되 새로운 판단에 필요한 설명은 생략하지 않는다.
- 공식 근거로 확인한 기술 동작, 프로젝트에 맞춘 제안, 실행 전 예상·가정을 구분한다. 사용자가 낯설어한다는 이유로 확인된 사실을 불확실하게 표현하지 않는다.
- 자연어 문서와 설명은 한국어로 작성한다. 실제 노드명·포트·API·검색어는 원문을 보존한다.

## 기존 기능·에셋 검토와 변경

- 구성 조사와 직접 작업의 실행 가능성은 [환경 규칙의 실행 수단과 조사 범위](<../Work/Environment Convention.md#실행-수단과-조사-범위>)를 따른다.
- 기존 Shader·Material·Texture·Sprite와 설정·사용처를 먼저 확인한다. Unity 기본 기능이나 설정 변경으로 충족할 수 있으면 우선 제안한다.
- 기존 에셋 재사용을 강제하지 않는다. 신규 제작이 더 적합하면 이유와 영향을 설명한다.
- 요청에 필요한 기능만 구성하며, 재사용 가능성만을 이유로 범용 Shader·추가 에셋·추상화를 만들지 않는다.
- 생성 전에 적합한 기존 폴더·에셋과 이름 충돌을 확인한다. [폴더·파일 구조](<../Work/Structure Convention.md>) 및 [공통 계층 명명](<../Work/Hierarchy Convention.md>)을 따른다.
- 공유 에셋 변경은 실제 사용처와 영향을 조사한다. 원본 수정·별도 생성의 대안을 제시하고 승인 없이 복제·교체·덮어쓰기·삭제하지 않는다.
- 생성·수정 대상, 주요 설정·연결 관계, 영향과 검증 방법을 브리핑한다. [승인 범위](<../Safety/Approval Convention.md>)를 따르며 이미 승인된 동일 범위는 반복 확인하지 않는다.

## 역할과 검증 상태

| 작업 | 기본 역할 |
|---|---|
| Shader Graph 작성·연결 | 사용자가 수행하고 에이전트가 안내·분석 |
| HLSL·셰이더 코드 | 승인 범위에서 에이전트 작성 및 상세 설명 |
| Material 에셋 생성·설정·할당 | 사용자 수행, 에이전트 안내 |
| Texture·Sprite 설정 | 사용자 수행, 에이전트 검토·제안 |
| Sprite Atlas 포함 목록 | 요청·승인 시 에이전트 등록 가능, 상세 범위는 Sprite 문서 참조 |

- 사용자 직접 변경 작업은 사전에 검토와 예상·가정까지만 보고한다. 변경 전 성공이나 최적화 효과를 검증했다고 표현하지 않는다.
- 사용자가 변경한 뒤 실제 적용 환경에서 테스트할 절차와 비교 지표를 안내하고, 전달받은 결과로 판단한다.
- 파일의 정적 분석, 컴파일, 실제 표시·동작 테스트와 성능 측정은 구분한다. 수행하지 않은 항목은 미검증으로 남긴다.
- 최적화 설명·검색 키워드·대안 검토·측정의 공통 절차는 [성능 컨벤션](<../Safety/Performance Convention.md>), 결과 기록은 [테스트·검증 컨벤션](<../Safety/Testing Convention.md>)을 따른다.
- 각 분야 문서에 해당 최적화의 개념·조건·장단점·검색어·테스트 방법을 둔다. 같은 기법은 한 곳에 설명하고 다른 문서에서 참조한다.

## 결과 보고

- 실제 변경한 에셋·코드·설정·연결 관계와 수행한 확인, 사용자 테스트 결과, 미검증 항목을 구분한다.
- 문서에는 상세 설명과 예시를 남기고, 사용자 보고는 필요한 변경 요약을 중심으로 한다.
