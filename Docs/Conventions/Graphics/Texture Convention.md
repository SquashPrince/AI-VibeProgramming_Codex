# Texture 컨벤션

## 목적과 역할

Texture는 색상·표면 방향·효과 적용 범위 등 이미지 또는 계산 데이터를 담는다.
같은 파일이라도 용도에 따라 설정이 달라진다. 색으로 표시할 이미지인지 계산용 데이터인지 먼저 확인한다.
공통 요구사항·승인은 [그래픽 공통 기준](<Common Convention.md>)을 따른다.

## 조사와 사용자 작업

- 색상·Normal Map·Mask 등 용도, 사용 Shader·Material·UI·Sprite, 기존 설정과 공유 사용처를 조사한다. 외형만으로 데이터 용도를 단정하지 않는다.
- 원본 이미지 수정, 임포트 설정 변경, 신규 이미지 제작을 구분한다. 원본과 `.meta`를 임의로 덮어쓰거나 변경·삭제하지 않는다.
- 에이전트는 설정·이유·대안·영향을 검토해 제안하고 사용자가 직접 변경하도록 안내한다.
- 변경 전에는 검토와 가정까지만 보고한다. 사용자가 변경한 다음 실제 적용 환경에서 테스트하도록 방법과 비교 지표를 제공한다.
- 사용자가 전달한 결과로 효과·부작용을 함께 판단한다. 사전 검토를 실제 검증으로 표현하지 않는다.

## 용도별 설정 설명

| 설정 | 개념과 제안 시 확인 사항 |
|---|---|
| Texture Type | 데이터 용도 구분. 일반 이미지·Normal Map·Sprite 등 실제 사용 방식 확인 |
| sRGB | 색상 해석과 변환에 관련된 설정. 색상 이미지와 선형 계산용 데이터의 차이를 설명하고 Shader에서의 사용 확인 |
| Max Size | 임포트되는 최대 크기. 원본 크기·실제 표시 크기·플랫폼별 제한 비교 |
| Compression·Format | GPU에서 사용할 표현 형식과 품질·메모리·지원 조건 검토 |
| Mipmap | 축소된 단계별 이미지를 사용. 먼 거리 화질·샘플링과 추가 메모리의 관계 설명 |
| Filter Mode | 샘플 사이를 읽는 방식. 픽셀 표현·확대·축소 품질에 맞춰 제안 |
| Wrap Mode | 좌표가 이미지 범위를 벗어날 때 반복·경계 처리 방식. 타일링·가장자리 용도 확인 |
| Alpha | 투명도인지 별도 계산 데이터인지 확인. 없는 알파를 가정하거나 제거하지 않음 |
| Read/Write | CPU 접근 필요 여부. 필요 없는 추가 CPU 데이터 보관 비용 검토 |

모든 Texture에 같은 값이나 설정을 강제하지 않는다. 설치 Unity·대상 플랫폼·렌더링 용도에 맞춰 메뉴명과 지원 범위를 확인한다.

## 압축 형식·품질 제안

- 압축 여부뿐 아니라 실제 플랫폼별 Format·품질·필요한 Override를 제안한다.
- 제안에는 용도·해상도·알파·목표 하드웨어·지원 조건을 포함한다. Normal Map·Mask의 채널 정확도와 색상 이미지의 시각적 품질을 구분한다.
- 권장 형식, 대체 형식, 비압축 비교안 중 필요한 선택지를 설명한다. 포맷 이름만 제시하고 끝내지 않는다.
- 블록 흔적·그라데이션 손상·가장자리·알파 손실·메모리·호환성의 예상 차이를 설명한다.
- 원본 PNG 등의 파일 압축, 배포 데이터 압축과 GPU Texture 압축을 구분한다. 디스크 크기 감소를 런타임 메모리 절약으로 단정하지 않는다.
- 어떤 품질 옵션이 선택한 형식에 실제로 적용되는지 확인한다. 모든 Format에서 같은 품질 설정이 작동한다고 가정하지 않는다.

### 압축 제안 형식 예시

| 항목 | 안내 내용 |
|---|---|
| 대상과 용도 | 어느 Texture를 어디에 사용하는지 |
| 환경 | 대상 플랫폼·GPU 지원 조건 |
| 권장 설정 | Format·크기·품질과 필요한 플랫폼 설정 |
| 근거·가정 | 예상 메모리·화질 변화와 선택 이유 |
| 대안 | 품질 우선·용량 우선 등의 비교와 제약 |
| 테스트 | 같은 시점·크기의 화면과 Texture 메모리 비교 |

예를 들어 Windows 대상이어도 모든 이미지에 한 가지 BC 계열 형식을 고정하지 않는다. 실제 알파·데이터 용도·지원 조건을 확인해 제안한다.

## 최적화 기법과 검색 키워드

| 기법 | 목적·조건과 주의점 | 검색 키워드 |
|---|---|---|
| 해상도 조절 | 표시 크기에 비해 큰 데이터를 줄이는 안. 작은 글자·경계·근접 시점 손상 확인 | Unity Texture Max Size memory |
| GPU 압축 | 데이터 크기와 읽기 비용 검토. 지원 형식·압축 흔적·데이터 정확도 확인 | Unity Texture Compression BC formats |
| Mipmap | 축소·거리 변화에서 샘플링과 깜빡임 검토. 추가 저장 공간이 필요하며 고정 크기 UI에 일괄 적용하지 않음 | Unity Mipmaps texture memory |
| Channel Packing | 별도 데이터를 RGBA 채널로 결합하는 안. 해상도·색 공간·압축·공유 수명·Shader 변경의 적합성 확인 | Unity Channel Packing mask texture |
| CPU 데이터 보관 조절 | CPU 읽기가 필요 없는 경우 추가 보관 비용 검토. 코드 사용처 확인 후 제안 | Unity Texture Read Write memory |

Channel Packing은 여러 데이터를 한 이미지에 담는 것으로, Sprite들을 배치하는 Atlas와 목적을 구분한다.
공통 설명·검색어·대안 검토 절차는 [성능 컨벤션](<../Safety/Performance Convention.md>)을 따른다.

## 사용자 변경 후 테스트 안내

1. 현재 설정과 비교 조건을 기록한다. 원본 파일은 유지한다.
2. 사용자가 제안 설정을 변경하고 임포트가 끝난 뒤 실제 Material·UI·Sprite에서 확인한다.
3. 같은 장면·카메라·해상도·거리에서 색상·투명도·경계·반복·Normal·Mask 결과 중 관련 항목을 비교한다.
4. Texture 메모리와 문제에 관련된 CPU·GPU 지표를 같은 조건에서 비교한다. 디스크 크기와 런타임 메모리를 구분한다.
5. 문제점·허용 가능한 품질·측정값을 바탕으로 유지·조정·복귀안을 검토한다.

미리보기만으로 실제 플랫폼의 품질·성능을 검증했다고 표현하지 않는다. 미확인 플랫폼·거리·부하 조건은 미검증으로 기록한다.
