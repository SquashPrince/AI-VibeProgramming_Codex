# 비동기 처리 컨벤션

## 목적

> 비동기 작업 구현시 사용할 비동기 처리 방식에 대해 확인하고 검토하기 위한 컨벤션이다.
> 
> AGENT는 대시 시간이 필요한 작업의 선택 기준과 취소·중복·실패 동작을 정한다.

## 선택 기준
- 비동기 처리 방식은 UniTask → Coroutine → Task 순서로 우선 검토한다.
- UniTask 설치 여부를 먼저 확인한다. 미설치 상태라면 도입 근거와 도입하지 않을 경우의 대안·영향을 설명하고 사용자에게 도입을 건의한다.
- UniTask 도입 여부에 대한 답변을 받기 전에는 다음 방식으로 임의 진행하지 않는다. 사용자 답변에 따라 Coroutine, Task 순서로 검토한다.
- 각 방식의 요구사항 적합성과 프로젝트 환경을 확인하며, 우선순위만을 이유로 부적합한 방식을 선택하지 않는다.
- 외부 패키지는 사용자 승인 없이 설치하지 않는다.

## 시작 전 정의
작업 소유자, 완료를 기다리는 주체, 재요청 시 무시·교체·대기열 정책, 취소 조건, 필요한 타임아웃, 성공·실패·취소의 상태를 정한다.

## 규칙
- 비활성화·파괴·Scene 전환 시 계속 실행할지 종료할지 정한다.
- 취소 후 도착한 이전 결과가 최신 상태를 덮어쓰지 않게 한다.
- 시작한 작업의 완료와 예외를 관찰할 책임자를 둔다.
- 취소와 오류를 구분하고 실패를 무시하거나 무한 재시도하지 않는다.
- Unity 객체 접근과 백그라운드 처리의 경계를 명시한다.
- 종료 경로에서도 구독·임시 상태·자원을 정리한다.

## 검증
연속 요청·실행 중 화면 종료·취소 직후 완료·실패 후 재시도를 확인한다.

## 프로젝트별 값
확정 값은 [프로젝트 값](<../../Project Values.md>), 미확정 값은 [프로젝트 설정](<../../Project Configuration.md>)을 따른다. 미확정 값의 확인 · 등록은 `project-setup` 스킬로 수행한다.
