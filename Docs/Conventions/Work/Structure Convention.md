# 폴더·파일 구조 컨벤션

> 상태: 공통 운영 기준.
> 대상: Unity/C# 기반 AI 보조 개발.

## 목적

에셋을 종류와 역할에 따라 분류하고, 기존 폴더를 활용하여 파일의 위치와 책임을 쉽게 찾는다.

## 폴더 분류 기준

- `Assets/` 바로 아래에 `Animations`, `Prefabs`, `Scripts` 등 에셋 종류별 폴더를 배치한다.
- 각 에셋 종류 폴더 안에서 실제 역할에 따라 분류한다.
- 프로젝트명·기능 영역·공통 영역 등을 묶기 위한 중간 분류 폴더를 에셋 종류 폴더 위에 두지 않는다.
  - `Shared`, `Features`, 프로젝트명 폴더는 이러한 분류 방식의 예시이며, 특정 이름만 금지하는 규칙이 아니다.
- 역할 폴더 안에서 추가 분류가 필요하다고 판단하면, 분리 이유와 제안 구조를 사용자에게 건의하고 답변을 받은 뒤 진행한다.
- 필요한 폴더만 생성하며, 사용하지 않는 빈 폴더를 미리 만들지 않는다.

### 구조 예시

아래 폴더명과 목록은 분류 방식을 보여주는 예시이며, 필수 생성 목록이 아니다.
실제 에셋 종류와 역할에 따라 이름과 구성을 정한다.

    Assets/
    ├─ Animations/
    │  ├─ Player/
    │  └─ Enemy/
    ├─ Materials/
    │  ├─ Environment/
    │  └─ Character/
    ├─ Prefabs/
    │  ├─ Player/
    │  ├─ Enemy/
    │  └─ UI/
    ├─ Scenes/
    └─ Scripts/
       ├─ Player/
       ├─ Enemy/
       └─ UI/

## 기존 구조 확인과 활용

- 폴더 계층의 명명 언어와 부모 문맥·번호의 불필요한 반복을 줄이는 기준은 [계층구조 컨벤션](<Hierarchy Convention.md>)의 `공통 계층 명명`을 따른다.
- 신규 파일·폴더 생성 또는 이동 전 기존 폴더, namespace, 유사 기능과 관련 에셋의 위치를 확인한다.
- 역할에 맞는 폴더가 이미 있으면 해당 폴더를 우선 사용한다.
- 동일하거나 유사한 역할의 폴더가 있는데 분류를 위해 불필요하게 새 폴더를 만들지 않는다.
- 기존 구조와 이 규칙이 다르더라도 승인 없이 파일·폴더를 이동하거나 이름을 변경하지 않는다.

## 생성·이동 전 검사와 보고

- 파일·폴더를 생성하거나 이동하기 전에 대상 경로의 기존 파일·폴더와 이름이 충돌하는지 검사한다.
- 같은 작업에서 생성·이동할 대상끼리도 이름과 경로가 충돌하는지 검사한다.
- 이름 충돌이 발견되면 충돌 대상과 해결 방안을 사용자에게 보고하고 답변을 받은 뒤 진행한다.
- 충돌 해결을 위해 임의로 덮어쓰거나 이름을 변경하거나 기존 대상을 삭제하지 않는다.
- 생성·이동 전 브리핑에서 다음 내용을 사용자에게 보고하고 승인을 받는다.
  - 생성·이동할 파일과 폴더
  - 기존 경로와 대상 경로. 신규 생성은 대상 경로만 기재한다.
  - 생성·이동 이유와 기존 폴더 활용 여부
  - 이름과 경로의 충돌 검사 결과
  - 참조 영향과 검증 방법
- 승인받은 범위 안에서 진행하며, 추가 생성·이동 또는 대상 경로 변경이 필요하면 다시 보고하고 승인을 받는다.
- 승인 범위와 추가 승인 대상의 공통 기준은 [승인 범위 컨벤션](<../Safety/Approval Convention.md>)을 따른다.

## 파일·타입·namespace

- 파일마다 대표 타입 하나를 기본으로 하고 파일명과 대표 타입명을 맞춘다. 작은 보조 타입은 필요하면 함께 둘 수 있다.
- 파일과 대표 타입의 이름은 [코드 컨벤션](<../Code/Code Convention.md>)의 명명 규칙을 따른다.
- namespace는 프로젝트명과 기능 영역을 기준으로 일관되게 정한다.
- Editor 전용 코드와 런타임 코드를 구분한다. 테스트 배치는 테스트 컨벤션과 프로젝트 구성을 따른다.
- namespace 일괄 변경과 Assembly Definition 추가는 영향과 승인 범위를 먼저 확인한다.

## Unity 에셋 이동

- Unity 에셋 이동 전 관련 참조와 경로 의존성을 확인하고, 이동 후 참조가 보존되었는지 검증한다.
- `.meta` 처리는 [승인 범위 컨벤션](<../Safety/Approval Convention.md>)을 따른다.

## 프로젝트별 값

확정 값은 [프로젝트 값](<../../Project Values.md>), 미확정 값은 [프로젝트 설정](<../../Project Configuration.md>)을 따른다.
미확정 값의 확인·등록은 `project-setup` 스킬로 수행한다.
