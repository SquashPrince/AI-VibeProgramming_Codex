# 폴더·파일 구조 컨벤션

> 상태: 공통 운영 기준.
> 대상: Unity/C# 기반 AI 보조 개발. 기존 승인 규칙과 사용자 확정 사항을 유지한다.

## 목적
기존 구조를 유지하면서 파일의 위치와 책임을 쉽게 찾는다.

## 규칙
- 신규 파일 생성 전 기존 폴더·namespace·유사 기능을 확인한다.
- 기능별 코드를 같은 영역에 모으고 여러 기능이 실제 공유하는 코드만 공통 영역에 둔다.
- 파일마다 대표 타입 하나를 기본으로 하고 파일명과 대표 타입명을 맞춘다. 작은 보조 타입은 필요하면 함께 둘 수 있다.
- 파일과 대표 타입의 이름은 [코드 컨벤션](<../Code/Code Convention.md>)의 명명 규칙을 따른다.
- namespace는 프로젝트명과 기능 영역을 기준으로 일관되게 정한다.
- Editor 전용 코드와 런타임 코드를 구분한다. 테스트 배치는 테스트 컨벤션과 프로젝트 구성을 따른다.
- 폴더 이동·namespace 일괄 변경·Assembly Definition 추가는 영향과 승인 범위를 먼저 확인한다.
- Unity 에셋 이동 시 참조 보존을 확인한다. `.meta` 처리는 [승인 범위 컨벤션](<../Safety/Approval Convention.md>)을 따른다.

## 신규 프로젝트 기본 배치
- Assets/<프로젝트명>/Features/<기능명>/
- Assets/<프로젝트명>/Shared/
- Assets/<프로젝트명>/Editor/
- Assets/<프로젝트명>/Tests/

위 구조는 예시이며 기존 프로젝트에 자동 적용하지 않는다.

## 프로젝트별 값
확정 값은 [프로젝트 값](<../../Project Values.md>), 미확정 값은 [프로젝트 설정](<../../Project Configuration.md>)을 따른다. 미확정 값의 확인 · 등록은 `project-setup` 스킬로 수행한다.
