# 실행 환경 컨벤션

> 상태: 공통 운영 기준. <br>
> 대상: Unity/C# 기반 AI 보조 개발. 기존 승인 규칙과 사용자 확정 사항을 유지한다.

## 목적
작업자마다 다른 버전과 설정으로 구현·검증하는 일을 줄인다.

## 프로젝트별 값
확정 값은 [프로젝트 값](<../../Project Values.md>), 미확정 값은 [프로젝트 설정](<../../Project Configuration.md>)을 따른다. 미확정 값의 확인 · 등록은 `project-setup` 스킬로 수행한다.

## 규칙
- 작업 전 프로젝트 파일과 기존 안내에서 실제 환경을 확인한다. 최신 버전이라고 추측하지 않는다.
- 문서와 실제 설정이 다르면 차이와 영향을 보고하고 기준을 확인한다.
- Editor·패키지·렌더 파이프라인 변경은 승인 범위를 먼저 확인한다.
- 환경 변경 시 이유·영향·되돌릴 방법·확인 결과를 기록한다.

## 실행 수단과 조사 범위

- 설정 변경과 에셋 생성의 구현 가능성, 현재 세션에서 에이전트가 실행할 수 있는지, 실제 실행 및 검증 결과를 구분한다. 사용자 승인을 실행 수단의 확보로 간주하지 않는다.
- Unity 작업 전 설치 버전과 대상 프로젝트, 사용 가능한 제어 도구, 권한과 지원 기능을 확인한다. 패키지가 설치돼 있거나 Unity가 실행 중이라는 사실만으로 에이전트의 직접 제어가 가능하다고 보고하지 않는다.
- 직접 수행을 약속하기 전에 사용할 실행 경로를 확인한다. 도구 호출, 승인된 Editor 자동화 스크립트 등 구체적인 수단과 실행 조건을 설명한다. 추가 스크립트나 파일이 필요하면 생성 대상과 영향, 실행 및 정리 방법을 승인받는다.
- 직접 실행이 불가능하거나 지원 여부를 확인하지 못했다면 가능한 조사와 사용자 설정 안내를 제공한다. 스크립트 작성만 마친 상태를 설정 적용 완료로 보고하지 않는다.
- 기존 구성은 접근 가능한 파일과 실제 도구로 관찰한 범위에서 조사한다. 저장되지 않은 Editor 변경, 읽지 못한 바이너리 데이터, 실행 중 생성되는 참조와 외부 의존성을 파일 검사만으로 모두 파악했다고 보고하지 않는다.
- 조사 결과는 직접 확인한 사실, 자료를 근거로 한 추정, 확인할 수 없었던 사항으로 구분한다. 확인 범위와 한계를 설명하고, 실제 실행과 화면 또는 청취 확인이 필요한 부분은 별도로 안내한다.

## 완료 확인
실제 검증에 사용한 Editor 버전·플랫폼을 보고하고, 환경이 없어 확인하지 못한 부분은 미검증으로 남긴다.
