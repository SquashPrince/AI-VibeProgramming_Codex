# 완료 조건 컨벤션

> 상태: 공통 운영 기준. <br>
> 대상: Unity/C# 기반 AI 보조 개발. 기존 승인 규칙과 사용자 확정 사항을 유지한다.

## 목적
구현 완료·검증 완료·병합 완료를 구분해 실제 상태를 공유한다.

## 시작 전
- Issue에 관찰 가능한 기대 동작과 확인 순서를 적는다. Issue를 만들지 않기로 한 작업은 [Workflow 규칙](<../../Codex/WorkflowRules.md>)의 `2. Github Issue`에 지정된 기록으로 대신한다.
- 정상 흐름·중요 실패 조건·기존 기능 영향과 대상 플랫폼을 정한다.

## 구현 완료
- 승인한 요구사항을 구현하고 임시 코드·불필요한 변경을 정리했다.
- 변경 파일과 연결 방법을 설명할 수 있다.
- 남은 문제와 확인하지 못한 동작을 분리해 기록했다.

## 검증 완료
- 변경 종류에 맞춰 합의한 검증을 실제로 수행하고 결과를 기록했다.
- 코드 변경이 있으면 새 컴파일 오류와 변경에 따른 기능 회귀 여부를 확인했다.
- 필수 검증이 남았다면 검증 완료라고 표기하지 않는다. 병합 가능 여부는 사용자·리뷰 담당자가 판단한다.

## 병합과 이후
- PR에는 영향 파일·확인 결과·리뷰 요청을 포함한다. 연결된 Issue가 있으면 해당 번호도 포함하고, 없으면 승인된 브리핑이나 작업 기록을 기준으로 작업 목적과 완료 조건을 설명한다.
- 작업 PR은 main-dev, 안정 버전 반영은 별도 PR로 main을 대상으로 한다.
- PR Merge 후 외부 업무 도구 갱신은 [업무 흐름 컨벤션](<Workflow Convention.md>)을 따른다.
- AI는 실제 수행한 검증과 한계를 보고하고 사용자는 최종 확인을 담당한다.
