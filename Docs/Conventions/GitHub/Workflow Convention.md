# 업무 흐름 컨벤션

## 기준 기록과 갱신
GitHub Issue·Commit·PR을 기준으로 나머지 업무 관리 도구를 관리한다.
PR이 Merge된 뒤 프로젝트에서 사용하기로 한 외부 업무 도구가 있다면, 해당 도구의 관련 작업 정보·Issue/PR 링크·확인 결과·상태를 갱신한다.
실행 확인이 남았다면 테스트 중으로, 기능상 문제 없음과 완료 기준 충족을 확인했다면 완료로 갱신한다.
개발 방향 변경과 중단·재개 내역은 우선 GitHub에 기록하고 외부 도구에는 PR Merge 후 갱신 시 반영한다.



## 동기화 절차
1. GitHub에서 실제 Merge 결과·연결 Issue·실행 확인 결과를 확인한다.
2. 프로젝트에서 사용하기로 한 도구에 담당자·목적·완료 기준·Issue/PR 링크·결과·상태를 갱신한다.
3. 자동 갱신이 있다면 반영 여부를 확인하고 누락만 수동 보완한다.
4. 도구 연결이나 권한이 없어 실패하면 GitHub에 동기화 미완료 사실과 대상 항목을 기록하고 보고한다.

## 사용 도구 지정
- GitHub는 필수이다. 저장소는 프로젝트 착수 시 지정한다.
- 프로젝트 착수 시 외부 업무 도구의 사용 여부를 실제 연결·설정과 사용자 답변으로 확인한다. 사용 중인 도구가 없으면 외부 도구 동기화 단계를 생략한다.
- Google 업무 시트·Jira·GitHub Projects는 선택 도구이며 전부 사용한다고 가정하지 않는다. 사용자가 이후 도구 도입을 알리면 도구·주소·담당자·상태 대응표를 확인해 프로젝트 설정에 등록하고, 도입 후 작업부터 갱신 대상으로 삼는다.
- 선택 도구의 주소·담당자·상태 대응표는 실제 도입 시 프로젝트 설정 문서에 등록한다. 미도입 도구는 갱신 대상이 아니다.
