# 3D 애니메이션 컨벤션

## 적용 범위

[애니메이션 공통 규칙](<Common Convention.md>)을 먼저 적용한다. 이 문서는 모델의 뼈대와 Avatar, 임포트, 리타기팅, 이동과 신체 부위별 조합, 실행 중 자세 보정의 기준을 다룬다.
특정 Rig 방식이나 패키지를 기본값으로 고정하지 않는다.

## Rig, Avatar와 임포트

| 용어 | 역할 |
|---|---|
| Rig | 캐릭터를 움직이는 뼈대 구조와 그 구조를 사용하는 설정 |
| Avatar | Unity가 모델의 뼈대를 해석하고 대응시키는 정보. 캐릭터 외형 자체를 뜻하지 않음 |
| 임포트 설정 | FBX 등 원본의 모델과 애니메이션 데이터를 Unity에서 읽고 사용할 방법 |
| 리타기팅 | 한 캐릭터의 동작을 다른 뼈대의 캐릭터에 적용하는 작업 |

- 모델 뼈대, 현재 Animation Type, Avatar의 구성 상태, Clip과 Controller, 대상 오브젝트와 코드 연결을 확인한다.
- 기존 설정과 요구에 따라 Humanoid, Generic 등 적합한 방식을 설명한다. 이미 동작하는 설정을 임의로 변경하지 않는다.
- Clip 구간 분리, 반복 설정, Avatar 지정, Controller 연결 같은 단순 설정은 요청과 승인 범위에서 수행한다.
- 뼈대 자체의 구조 변경, 자세와 동작의 세밀한 보정은 사용자 작업을 기본으로 안내한다. 역할 세부 기준은 공통 문서를 따른다.
- 하나의 모델 파일에 여러 Clip이 들어 있으면 임포트 변경이 다른 Clip과 사용처에 주는 영향을 먼저 확인한다.
- 원본에서 가져온 Clip과 별도로 편집 가능한 Clip의 차이, 재임포트와 원본 갱신의 영향을 확인한다. 요청 없이 추출하거나 복제하지 않는다.
- 파일과 메타데이터의 변경 승인은 기존 안전 규칙을 따른다. 단순 설정이라는 이유로 승인 절차를 생략하지 않는다.

## 다른 캐릭터의 동작 적용

- Asset Store 캐릭터에 Mixamo 동작을 연결하는 요청처럼 출처가 다른 파일은 각 Rig와 Avatar, Clip, 기존 Controller와 이동 코드를 조사한다.
- 사람형 모델은 Humanoid 리타기팅 가능성을 검토한다. 적절하게 구성된 Avatar가 필요하며, 파일 확인 전에 적용 가능하다고 확정하지 않는다.
- 캐릭터와 애니메이션의 본 이름이 다르다는 이유만으로 이름 변경부터 제안하지 않는다. Humanoid는 Avatar의 신체 역할 대응을 활용하므로 이름 차이만으로 적용 실패를 단정할 수 없다.
- 먼저 Animation Type, Avatar의 유효성과 본 대응, 실제 Animator 연결을 확인한다. Generic 등 다른 방식은 해당 뼈대 계층과 경로의 일치 조건을 따로 조사한다.
- Avatar 대응으로 해결할 수 있으면 변경할 연결을 설명하고 승인 후 설정한다. 뼈대 이름과 계층은 임의로 고치지 않는다.
- 구조 변경이 필요하면 이유와 기존 참조에 미치는 영향을 보고하고 사용자 편집 방법을 안내한다.
- 사용자가 이미 받은 파일의 적용 요청은 해당 파일의 사용 작업이다. 별도 외부 에셋을 새로 추천할 때는 공통 무료 기준을 적용한다.

### 단계별 적용 예시

1. 캐릭터와 받은 Walk, Run 파일 확인 → 확인: Rig와 Avatar, 기존 연결, 필요한 설정
2. 승인한 임포트와 테스트 재생 연결 → 확인: 대상 캐릭터에 동작이 적용되는지
3. 후속 지시에 따른 Controller 또는 Blend Tree 구성 → 확인: 파라미터와 기준값, 기존 참조 영향
4. 후속 지시에 따른 플레이어 코드 연결 → 확인: 실제 이동과 애니메이션의 관계

팔 뒤틀림이나 발 미끄러짐이 발견되면 설정, 체형 차이, 원본 보정의 가능성을 구분한다. 원인 조사 없이 뼈대나 Clip을 자동 수정하지 않는다.

## Root Motion과 실제 이동

Root Motion은 애니메이션에서 나온 이동과 회전을 실제 캐릭터 제어에 활용하는 방식이다. 코드 이동은 코드가 이동량을 정하고 애니메이션이 모습을 표현하는 방식이다. 두 방식을 역할별로 조합할 수도 있다.

- 기존 이동 코드, 물리 컴포넌트와 충돌 처리, Clip의 이동 정보를 확인한다.
- 조작 반응, 이동 거리와 동작의 일치, 충돌 요구를 근거로 코드 이동과 Root Motion 및 조합의 장단점을 설명한다.
- 같은 이동이나 회전을 코드와 애니메이션이 의도치 않게 중복 적용하지 않도록 담당 주체와 전환 시점을 정한다.
- 애니메이션 연결을 이유로 기존 이동 방식을 바꾸거나 Apply Root Motion과 임포트의 이동 설정을 임의로 변경하지 않는다.
- Root Motion만 켜면 모든 충돌 처리가 해결된다고 설명하지 않는다. 실제 이동 구조에 맞춰 애니메이션 이동량과 충돌 처리를 연결하는 안을 제시한다.
- 이동 애니메이션을 적용할 때 충돌체의 이동, 장애물에 막힌 경우, 정상 종료와 취소 후 위치 및 다음 행동까지 함께 설계한다.
- 승인된 설정과 코드 연결은 에이전트가 수행하고, 원본 이동 궤적의 세밀한 편집은 사용자가 수행하도록 안내한다.

### 구르기 예시

- 장애물이 없으면 요구한 이동을 수행하고 도착한 위치를 유지한다.
- 벽이 있으면 실제 이동 가능한 위치까지만 이동한다. 원래 예정한 이동 거리의 완주를 강제하지 않는다.
- 모델과 충돌체가 함께 이동하게 하며, 종료 후 실제 도착 위치에서 대기나 이동을 이어가도록 설계한다.
- 벽에 막혔을 때 동작을 끝까지 재생할지 중단할지, 중간 취소 시 어느 상태로 돌아갈지 선택받는다.
- 이동 거리, 충돌, 발 미끄러짐, 종료 시 위치 복귀나 튐, 취소 후 일반 이동 복구를 확인한다.

CharacterController를 쓰는 경우 애니메이션이나 코드에서 정한 이동량을 CharacterController.Move에 전달하는 구성을 검토할 수 있다. Rigidbody 등 다른 구조는 그 구조에 맞춰 제안한다. 예시를 이유로 기존 이동 컴포넌트를 교체하지 않는다.

## Blend Tree와 신체별 동작 조합

일반 선택 기준과 역할은 [공통 규칙](<Common Convention.md>)을 따른다.

- 속도나 방향에 따라 섞는 값과 실제 게임 코드가 전달하는 값의 의미를 맞춘다. Walk와 Run을 단순히 배치했다고 실제 이동에 연결됐다고 보고하지 않는다.
- “달리면서 총을 쏜다”는 요구에는 기존 하체 이동과 상체 사격을 분리할 필요가 있는지 확인한다.
- Layer의 Override와 Additive 등 혼합 방식은 목적과 원본 동작 조건에 맞춰 설명한다. Layer 순서와 영향도, 적용 범위도 함께 제안한다.
- Avatar Mask는 해당 Layer의 영향을 받을 신체 부위를 정하는 용도로 검토한다. 기존 동작과 같은 부위를 제어하는지 확인한다.
- 요청받은 Blend Tree, Layer와 Mask의 생성, 기본 연결과 파라미터 설정은 에이전트가 수행할 수 있다.
- 블렌딩 기준값, 전환 시간, Layer 영향도와 Mask 적용 부위를 실제 화면에서 세밀하게 조정하는 작업은 사용자가 수행한다. 에이전트는 값의 의미와 예상 변화, 조작 방법을 안내한다.
- 조준과 공격 중 의도하지 않은 부위가 움직이는지, 전환이 튀는지, 중단 후 기존 동작으로 돌아오는지 확인한다.

## IK와 Animation Rigging

IK는 손이나 발 같은 끝부분을 목표 위치에 맞추도록 관절을 계산하는 방식이다. Animation Rigging 같은 도구로 재생 중인 동작에 자세 보정을 더하는 구성을 검토할 수 있다.

- 원본 동작과 기존 연결 설정으로 해결 가능한지 확인하고 실행 중 자세 보정이 필요한 경우 방식을 제안한다.
- Unity 기본 기능, 공식 패키지와 외부 후보는 공통 추천 기준으로 비교한다. 외부 패키지 추천을 IK 전용 규칙으로 한정하지 않는다.
- 목표 오브젝트와 컴포넌트, 참조의 기본 구성은 요청 범위에서 에이전트가 수행한다.
- 손발 위치와 회전, 관절 방향과 보정 강도의 세밀한 조정은 사용자가 수행한다. 에이전트는 조정 항목과 의미를 안내한다.
- 어떤 상태에서 보정을 적용하고 해제할지 정한다. 무기 교체, 대상 파괴, 비활성화와 재사용 시 참조와 보정 상태의 정리도 확인한다.
- 애니메이션과 보정이 같은 부위를 제어하는 순서와 영향을 조사하고, 기존 Rig와 제약 설정을 임의로 변경하지 않는다.
- 새 패키지의 설치와 도입 초기 설정은 공통 역할을 따른다. 도입 후 요청한 구성과 연결을 구분한다.

예를 들어 왼손이 총 손잡이를 잡도록 요청하면 기본 목표와 참조를 연결하고, 정확한 손 위치와 팔꿈치 방향은 사용자가 실제 동작을 보며 조정하도록 안내한다.

## 최적화와 확인 항목

측정과 승인 절차는 [공통 규칙](<Common Convention.md>)을 따른다. 아래 항목은 원인에 맞춰 선택하며 효과를 미리 보장하지 않는다.

| 기법 또는 조사 대상 | 적용 조건과 주의점 | 검색 키워드와 확인 방법 |
|---|---|---|
| Animator Culling | 보이지 않는 대상의 처리 비용 조사. 화면 밖 동작과 이벤트 등 게임 상태에 주는 영향 확인 필요 | Unity Animator Culling Mode / 동일 대상 수에서 CPU와 화면 복귀 후 상태 비교 |
| 동작과 제약 계산 | 실제 비용이 큰 Layer, 동작 혼합, IK와 제약 조사. 계산을 줄이면 자세와 전환 품질이 바뀔 수 있음 | Unity Animator profiling Animation Rigging profiling / 동일 동작에서 CPU와 자세, 이벤트 비교 |

- Rig와 Avatar 변경 후 자세, 반복 경계, 손발 정렬과 기존 사용처의 영향을 확인한다.
- 리타기팅의 파일 설정 확인, 실제 캐릭터 재생과 성능 측정은 각각 구분해 보고한다.
