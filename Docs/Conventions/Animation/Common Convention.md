# 애니메이션 공통 컨벤션

## 목적과 적용 범위

애니메이션을 만들거나 수정할 때 요구를 해석하고, 적합한 방식과 작업 범위를 제안하는 기준이다.
2D와 3D, 캐릭터 동작, UI 변화, 시간에 따른 연출에 공통 적용한다. 특정 도구를 기본 정답으로 고정하지 않는다.

| 문서 | 참조 시점 |
|---|---|
| [2D](<2D Convention.md>) | Sprite 프레임, Unity 2D Animation, 외부 2D 도구 작업 |
| [3D](<3D Convention.md>) | Rig와 Avatar, Clip 임포트, 리타기팅, Root Motion, 신체별 동작과 IK |

분야별 예시와 도구 목록은 필수 도입 목록이 아니다. 필요한 분야만 추가로 읽는다.

## 요구와 기존 구성 확인

- 사용자가 원하는 움직임을 자연어로 설명해도 적절한 기술과 작업안으로 연결한다. 도구 이름을 먼저 알아야 하는 것으로 요구하지 않는다.
- 적용 대상, 시작 조건, 반복 여부, 완료 모습, 중단 조건과 연결할 게임 동작을 기존 자료에서 먼저 확인한다. 이미 제공된 정보는 재질문하지 않는다.
- 기존 Clip, Controller, 상태, 전환, 파라미터, Layer, 이벤트와 코드 참조를 확인한다. 공유 에셋의 사용처와 변경 영향을 조사한다.
- [프로젝트 값](<../../Project Values.md>)과 실제 환경을 확인하고, 차이는 [환경 컨벤션](<../Work/Environment Convention.md>)에 따라 보고한다.
- 원본 수정과 별도 제작의 실질적인 대안을 설명한다. 복사본 제작도 임의로 수행하지 않는다.
- **사용자가 명시적으로 수정을 지시하지 않은 기존 애니메이션은 임의로 수정하지 않는다.** Clip뿐 아니라 Controller와 전환, 파라미터, Blend Tree, Layer, 이벤트, Rig 등의 기존 구성도 포함한다.
- 문제나 최적화 기회를 발견하면 원인과 변경안을 먼저 보고한다. 다른 기능의 구현 요청을 기존 애니메이션 전체의 변경 승인으로 확대하지 않는다.
- 요청한 연결에 필요한 기존 구성 변경은 대상과 영향을 브리핑에 명시한다. 실제 승인 범위는 [승인 범위 컨벤션](<../Safety/Approval Convention.md>)을 따른다.

## 설명과 방식 선택

- 처음 사용하는 용어는 역할과 화면에서 보이는 결과를 쉬운 말과 예시로 설명한다.
- 실질적인 대안의 동작 방식, 장단점, 권장 이유와 기존 방식에서 달라지는 점을 설명한다. 사소한 세부 선택마다 질문하지 않는다.
- 공식 자료로 확인한 기술 동작, 프로젝트에 맞춘 제안, 실행 전 가정, 실제 검증 결과를 구분한다.
- 사용자 안내에는 실제 메뉴와 설정 항목 이름, 값과 선택 이유, 확인 순서를 제공한다.
- 문서는 상세 설명과 예시를 포함하고, 진행 보고는 변경 부분을 중심으로 요약한다. 후속 단계마다 전체 구성을 반복 설명하지 않는다.

## 공식 기능과 외부 도구 제안

- 모든 애니메이션 분야에서 요구에 적합한 Unity 기본 기능, 공식 지원 패키지, 기존 에셋과 외부 도구를 선제적으로 검토하고 제안한다. 사용자가 패키지를 먼저 언급할 필요는 없다.
- 공식 지원 여부와 널리 사용되는 정도를 구분한다. 유명하다는 이유만으로 추천하지 않고, 실제 요구와 환경에 맞는 후보만 비교한다.
- 역할이 다른 도구를 무조건 대체재로 비교하지 않는다. 캐릭터 상태 전환, 수치 변화, 시간 연출, 자세 보정처럼 역할을 나눠 함께 쓰는 구성이 적합할 수 있다.
- 구체적인 추천 전 현재 버전의 공식 문서와 제작자 자료로 기능, 설치 여부, 버전 호환성, 유지보수 상태, 라이선스와 비용을 확인한다. 미확인 사항은 명시한다.
- 사용자가 별도로 명시하지 않으면 도구와 패키지는 무료로 사용할 수 있는 후보만 추천한다. 무료 사용 범위와 제한을 확인한다.
- Clip 등 콘텐츠 에셋은 별도 요청이 없으면 CC0이면서 무료인 것만 추천한다. 도구와 패키지는 CC0을 필수로 하지 않으며 해당 라이선스의 사용 조건과 고지 의무를 설명한다.
- 유료 제품, 체험판, 요구 기능에 유료 전환이 필요한 후보는 사용자가 명시적으로 요청한 경우에만 제안한다. 이미 사용 중인 유료 도구의 조사와 작업 안내를 신규 도입 추천으로 취급하지 않는다.
- 적합한 무료 후보가 없거나 호환성이 불명확하면 그 사실을 설명한다. 외부 후보를 제시하기 위해 부적합한 도구를 억지로 추천하지 않는다.
- 다운로드, 설치, 프로젝트 추가와 도입을 위한 초기 설정은 사용자가 직접 수행한다. 에이전트는 절차, 설정 이유와 정상 도입 확인 방법을 안내한다.
- 추천이나 도구 선택 승인을 에이전트의 설치 승인으로 해석하지 않는다. 도입 완료 후 애니메이션 구성과 참조 연결은 아래 작업 역할에 따라 수행한다.

Animator, Timeline, Animation Rigging, DOTween, PrimeTween, LitMotion, Animancer 등은 요구에 따라 검토할 수 있는 예시다. 목록에 있다는 이유로 무료 조건이나 호환성 검사를 생략하거나 설치를 확정하지 않는다. 추천 방식 확인용으로 제시한 후보도 도입 승인으로 기록하지 않는다.

## 작업 역할

| 작업 | 기본 역할 |
|---|---|
| 기존 구성 조사와 연결안 제안 | 에이전트가 파일과 사용 가능한 도구로 확인하고 설명 |
| 정렬된 Sprite로 Clip 생성 | 사용자 요청에 따라 에이전트가 승인된 순서와 값으로 수행 |
| Animator 상태, 전환, 파라미터 구성 | 에이전트가 승인된 기본 설정과 연결 수행 |
| Blend Tree, Layer, Avatar Mask 구성 | 에이전트가 승인된 생성과 기본 연결 수행 |
| Rig, Avatar와 애니메이션 임포트 설정 | 에이전트가 지원 범위에서 승인된 단순 설정 수행 |
| 코드 작성과 플레이어 재생 연결 | 에이전트가 승인된 코드와 파일 범위에서 수행 |
| 세밀한 시각 편집과 동작 보정 | 사용자가 직접 편집하고 에이전트가 방법 안내 |
| 패키지 도입 | 사용자가 수행하고 에이전트가 안내 |

- 세밀한 편집에는 키프레임과 커브, 자세, 변형, 블렌딩 기준값, 전환 시간, Layer 영향도, Mask 부위, IK 목표 위치와 보정 강도 조정 등이 포함된다.
- 기본 설정과 사용자가 조정할 항목을 구분한다. 시각적인 미세 조정값을 에이전트가 임의로 확정하지 않는다.
- 세밀한 편집도 사용자가 직접 수행을 요청하면 도구 지원 범위, 예상 시간과 토큰 부담을 설명하고 작업 범위를 정한다. 정확한 사용량을 근거 없이 보장하지 않는다.
- 지원 도구가 없거나 직접 편집이 부적합하면 가능한 파일 검사와 사용자 설정 안내를 제시한다. 화면을 조작하지 않았는데 에디터에서 설정한 것으로 보고하지 않는다.
- 폴더와 오브젝트 명명은 [계층구조](<../Work/Hierarchy Convention.md>), 파일 위치는 [구조 규칙](<../Work/Structure Convention.md>)을 따른다. Sprite 원본 설정의 역할은 [Sprite 규칙](<../Graphics/Sprite Convention.md>)을 참조한다.

## 단계별 요청과 승인

- 폴더 경로만 제공하면 먼저 확인 요청으로 해석한다. 전체 Clip 생성과 Controller 설정, 플레이어 연결까지 일괄 승인으로 확대하지 않는다.
- “Run 폴더로 애니메이션을 만들어줘”는 Clip 생성 요청이다. 파일을 확인하고 생성 경로, 프레임 순서, 속도와 반복 여부를 제안한다. 이미 정한 기준은 다시 묻지 않는다.
- “지정한 Controller에서 기존 Walk와 전환되게 해줘”는 요청한 상태와 연결 작업으로 해석한다. 실제 구성과 요구를 확인해 전환 방식과 필요한 변경을 제안한다.
- “Blend Tree로 만들어줘”는 해당 구성으로 작업안을 바꾼다. Blend Tree에도 제어 파라미터가 필요하므로 적합한 기존 파라미터를 먼저 확인한다.
- “플레이어와 연결해줘”는 Animator와 이동 코드 등 실제 재생 연결을 조사하고 변경안을 제안하는 요청이다. 관련 없는 이동 방식이나 Layer를 함께 변경하지 않는다.
- 각 단계의 승인된 작업을 완료한 뒤 결과와 다음 가능한 작업을 보고하고 다음 지시를 기다린다. 후속 단계는 자동 실행하지 않는다.
- 이미 승인한 동일한 방법과 범위는 재승인을 요구하지 않는다. 새로운 파일과 영향 범위는 승인 규칙에 따라 추가 보고한다.

### 단계별 보고 예시

Run Clip 생성 승인을 받아 실제 생성과 파일 검사를 마친 경우의 보고 예시다. 수치는 설명용이다.

> Run Clip을 생성했습니다.
>
> - 프레임: Run_01부터 Run_08까지 8개
> - 재생 속도: 초당 12프레임
> - 반복: 켜짐
> - 수행: 프레임 순서와 파일 설정 확인
> - 미수행: Unity 실제 재생 확인
>
> 다음 요청에 따라 지정한 Controller의 Walk와 연결할 수 있습니다.

## 재생과 중단 정책

- 입력, 상태 변화, 이벤트 등 재생 요청 조건과 재생 주체를 정한다.
- 재생 중 중복 요청을 무시할지, 재시작할지, 이어 처리할지 요구에 맞춰 제안한다. 정책을 일괄 고정하지 않는다.
- 정상 완료와 취소 또는 중단을 구분하고 각각의 처리와 정리 책임을 정한다.
- 중단 시 현재 모습 유지, 초기 상태 복귀, 최종 상태 적용 등의 선택과 영향을 설명한다.
- 비활성화, 파괴, Scene 전환, 풀 반환과 재사용 시 진행 중인 동작의 종료와 참조 정리를 확인한다.
- Animator, 트윈, 이동 코드 등이 같은 위치나 회전 등을 의도치 않게 동시에 제어하지 않도록 담당 주체와 전환 시점을 정한다.
- 일시정지와 슬로모션의 영향을 받을지 확인하고 시간 기준을 안내한다.
- 이미 합의한 재생 정책은 후속 작업마다 반복 질문하지 않는다.

## 게임 로직 연결

- 애니메이션을 시작하는 주체와 실제 게임 상태를 관리하는 주체를 명확히 한다.
- 데미지나 아이템 지급을 단순히 재생 시간이 지났다는 이유로 실행하지 않는다. 필요한 시점과 동기화 방식을 제안한다.
- Animation Event, 코드 상태, 완료 콜백 등 요구와 도구에 맞는 방법을 비교한다. 모든 동작에 하나의 연결 방식을 강제하지 않는다.
- 중단된 동작의 완료 처리, 반복 재생과 중복 요청에 따른 판정 중복을 방지할 정책을 정한다.
- 이벤트와 파라미터 이름은 짧고 역할이 명확하게 제안한다. 기존 코드 연결을 확인하고 사용 중인 이름을 임의로 변경하거나 삭제하지 않는다.
- 공격 판정의 시작뿐 아니라 취소와 정상 종료 시 판정 종료도 함께 정한다.
- 구독 수명과 참조 정리는 [이벤트](<../Code/Event Convention.md>)와 [참조 관리](<../Code/Reference Convention.md>), 지연과 취소 구현은 [비동기 규칙](<../Code/Async Convention.md>)을 따른다.

## Blend Tree와 Layer 선택

- 상태 전환으로 충분한지, 연속적인 값에 따라 동작을 섞어야 하는지 비교한다. Blend Tree와 전환을 무조건 대체재로 취급하지 않는다.
- Blend Tree의 파라미터 의미와 실제 전달값의 범위를 확인한다. 기본 기준값과 사용자가 실제 화면을 보며 조정할 값을 구분한다.
- 서로 다른 동작을 함께 적용할 필요가 있을 때 Layer를 검토한다. 목적 없이 Layer를 늘리지 않는다.
- Layer의 순서, 혼합 방식, 영향도와 적용 범위를 설명하고 같은 속성을 제어하는 기존 동작과 충돌하는지 확인한다.
- 사용자가 Bool 전환 대신 Blend Tree를 지정했다면 이미 선택한 방식을 다시 묻지 않고 필요한 구성과 변경만 제안한다.
- 신체 부위별 조합과 Mask 적용은 [3D 규칙](<3D Convention.md>)을 참조한다. Blend Tree와 Layer 자체를 3D 전용 기능으로 설명하지 않는다.

## 검증 안내

검증 공통 절차와 기록은 [테스트 규칙](<../Safety/Testing Convention.md>)을 따른다. 아래 항목에서 변경한 동작과 영향을 받는 연결에 관련된 것만 선택한다.

| 확인 대상 | 애니메이션 확인 내용 |
|---|---|
| 정상 재생 | 시작 조건, 순서, 반복, 종료 후 모습 |
| 중복 요청과 중단 | 합의한 무시, 재시작, 취소와 정리 정책 |
| 오브젝트 수명 | 관련된 비활성화, 파괴, Scene 전환, 풀 재사용 |
| 게임 로직 | 필요한 시점의 판정, 중복 실행과 취소 후 오작동 여부 |
| 실제 화면 | 전환 자세가 튀는지, 위치와 크기가 어긋나는지, 동작과 판정이 맞는지 |

- 합의한 동작, 테스트 방법, 예상 결과, 실제 확인 여부 순으로 안내한다.
- 파일 분석과 에디터 실제 재생 결과를 구분한다. 사용자 수행 항목과 직접 수행한 검증을 나누고 미실행은 미검증으로 남긴다.
- 예를 들어 공격 연결은 정상 공격, 연속 입력, 피격 취소, 비활성화 후 재공격을 관련 범위에서 확인한다. 버튼 확대 연출에 공격 판정 검사를 요구하지 않는다.

## 최적화 검토

- 시점, 측정 절차, 기법 설명과 검색어 제공은 [성능 규칙](<../Safety/Performance Convention.md>)을 따른다. 실제 성능 요구나 문제가 있으면 조사하고, 범위 밖 개선은 제안 후 승인받는다.
- 애니메이션 계산, 관련 코드, 렌더링 중 어디에서 비용이 발생하는지 구분한다.
- 캐릭터 수, 동시에 재생하는 동작, 보이는 대상 수 등 관련 조건을 맞춰 전후 비교한다.
- 비용 감소와 함께 움직임의 자연스러움, 이벤트 실행, 화면 밖에서 돌아왔을 때의 상태를 확인한다.
- 각 분야의 관련 기법만 선택해 개념, 조건, 장단점, 검색어와 테스트 방법을 설명한다. 아직 측정하지 않은 효과를 개선 완료로 보고하지 않는다.
- 최적화가 기존 애니메이션의 변경 허가를 대신하지 않는다.
