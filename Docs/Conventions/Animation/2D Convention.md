# 2D 애니메이션 컨벤션

## 적용 범위

[애니메이션 공통 규칙](<Common Convention.md>)을 먼저 적용한다. 이 문서는 프레임 애니메이션, Unity 2D Animation, 외부 2D 제작 도구의 차이를 다룬다.
역할과 승인, 도구 추천과 설치, 재생 제어와 검증의 공통 기준은 복사하지 않는다.

## 프레임 애니메이션

프레임 애니메이션은 Sprite를 순서대로 표시해 움직임을 만드는 방식이다. 프레임의 순서와 표시 시간이 동작의 모습과 속도를 결정한다.

### 기존 구성과 생성 조건

- 대상 폴더의 Texture와 실제 Sprite, 이름, 순서, 프레임별 표시 시간, 반복 여부, 기존 Clip과 Controller 연결을 확인한다.
- 파일명 숫자 순서와 단순 문자열 순서가 다른지 확인한다. 예를 들어 Run_1, Run_2, Run_10이 의도한 순서인지 확인하며 확장자만 보고 프레임을 확정하지 않는다.
- 여러 파일이 각각 한 Sprite인지, 한 Texture에 여러 Sprite가 들어 있는지 구분한다.
- 생성 경로와 이름, 프레임 순서, 속도, 반복 여부를 제안한다. 이미 정해진 기준은 재질문하지 않는다.
- 프레임이 불명확하면 관련 이미지를 확인하거나 사용자에게 순서를 묻는다. 파일명만으로 추측해 기존 순서를 바꾸지 않는다.
- 기존 Clip이 있으면 덮어쓰지 않고 먼저 보고한다. 포함된 이벤트와 참조도 확인한다.

### 사용자 편집과 단순 작업

- 준비된 Sprite를 순서대로 묶는 Clip 생성은 공통 규칙의 단순 작업으로 수행할 수 있다.
- 이미지 원본 편집, Sprite 분할과 Pivot, 크기 설정은 [Sprite 규칙](<../Graphics/Sprite Convention.md>)을 참조한다. Clip 생성 요청을 해당 설정 전체의 변경 요청으로 확대하지 않는다.
- 프레임이 바뀔 때 위치나 크기가 튀면 원본 이미지의 정렬, 분할 영역, Pivot과 크기 설정을 조사하고 수정 위치를 설명한다.
- 속도 조절은 전체 재생 속도와 프레임별 표시 시간의 차이를 설명한다. 개별 동작의 자연스러움을 보며 조정하는 세밀한 편집은 사용자에게 안내한다.
- 방향별 이미지 사용, 종료 후 상태, 공격 판정 시점은 요구에 맞춰 제안하며 이미지 순서만으로 임의 확정하지 않는다.

### 작업 예시

“Run 폴더로 애니메이션을 만들어줘”라고 요청하면 파일을 확인하고 Run Clip 생성 범위를 제안한다.
승인 후 Clip과 설정을 확인해 보고하며, Controller 연결이나 플레이어 코드 수정은 후속 지시 없이 진행하지 않는다.
사용자가 연결도 요청하면 기존 Controller와 코드를 조사하고 공통 규칙의 단계별 절차로 이어간다.

## Unity 2D Animation

Sprite에 뼈대를 구성하고, 이미지의 각 부분이 뼈대를 얼마나 따라갈지 정해 움직이는 방식이다.
변형에 쓰는 메시와 가중치가 관절 주변의 접힘과 늘어남에 영향을 주므로 재생 연결과 시각적인 보정을 구분한다.

- 원본 이미지, 뼈대 구조, 변형 메시와 가중치, 관련 컴포넌트, Clip과 Controller를 확인한다.
- 뼈대 위치, 메시와 가중치의 세밀한 조정은 사용자가 직접 수행하고 에이전트가 의미와 편집 방법을 안내한다.
- 컴포넌트와 참조, Clip과 Controller의 단순 구성은 공통 역할에 따라 요청 범위에서 수행한다. 새 패키지 도입과 도입 후 작업을 구분한다.
- “팔꿈치를 접으면 이미지가 찌그러진다”는 경우 관련 뼈대와 메시, 가중치의 문제를 조사하고 조정할 위치를 안내한다. 기존 구성을 자동 수정하지 않는다.
- 사용자가 세밀한 편집도 직접 요청하면 공통 규칙에 따라 지원 도구와 부담, 변경 범위를 먼저 확인한다.
- 도구 버전의 실제 메뉴와 지원 기능을 확인해 안내한다. 예시 문서 버전을 설치 버전으로 간주하지 않는다.

## 외부 2D 도구 — 초안 승인

**이 절만 초안 상태다.** Spine, Live2D 등 외부 2D 도구는 실제 사용 가능성이 낮아 세부 기준을 확정하지 않고 아래 초안을 승인했다. 다른 공통 규칙과 Unity 2D Animation 및 3D 규칙까지 초안으로 취급하지 않는다.

### 최초 사용 또는 제안 시 확인

사용자가 해당 도구의 사용을 처음 명시하거나 에이전트가 해당 도구를 처음 제안할 때 아래 강조 안내를 제공한다. 단순 예시 언급을 설치나 사용 승인으로 취급하지 않는다.

> ⚠️ **이 도구의 작업 규칙은 아직 ‘초안’ 상태입니다.**
>
> 이전에는 실제 사용을 전제로 세부 기준까지 확정하지 않았습니다.
>
> **이번에 사용할 작업에 맞춰 규칙을 다시 검토하고 확정할까요?**
>
> 1. **규칙 재검토 후 진행**
> 2. 기존 초안 기준으로 진행

- 재검토를 선택하면 해당 작업에 필요한 기준부터 논의한다. 기존 초안을 선택하면 승인 범위에서 초안 기준을 적용한다.
- 같은 도구에 대해 이미 받은 답변은 반복 질문하지 않는다. 답변과 적용 범위는 해당 작업 기록에 남긴다.
- 이 안내는 공통 무료 추천 조건을 해제하지 않는다. 조건에 맞지 않는 신규 도입 후보를 초안 확인만으로 추천하지 않는다.

### 원본과 Unity 데이터의 작업 기준

- 확장자만으로 도구를 특정하지 않는다. 특히 JSON은 데이터 형식이며 도구 이름이 아니다.
- 도구와 원본 파일, 내보낸 데이터, Unity 연결 구성을 확인한다.
- 원본의 그림 변형, 뼈대, 표정과 세밀한 동작 편집은 사용자 작업을 기본으로 안내한다.
- Unity의 컴포넌트, 참조, 재생 코드와 상태 연결은 지원 범위에서 단계별로 수행한다.
- 문제의 위치를 원본 제작, 내보내기, Unity 설정으로 구분하고 수정할 위치와 이유를 설명한다.
- 내보낸 데이터를 임의로 직접 수정하지 않는다. 재내보내기로 덮어써지는지 확인하고 적절한 수정 위치를 제안한다.
- 기존 프로젝트의 유료 도구를 조사하거나 작업 방법을 안내하는 것과 새로 추천하는 것을 구분한다. 비용과 도입은 공통 규칙을 적용한다.

예를 들어 Unity에서 표정이 바뀌지 않으면 원본 표정 정보, 내보내기 결과와 Unity의 제어값 연결을 확인하고 해당 단계의 변경안을 보고한다.

## 최적화와 확인 항목

공통 절차는 [애니메이션 공통 규칙](<Common Convention.md>)을 따른다. 아래 항목은 조사 후보이며 자동 변경 목록이 아니다.

| 분야 | 조사 조건과 비용 | 검색 키워드와 확인 방법 |
|---|---|---|
| 프레임과 Texture 사용 | 프레임 수와 해상도가 메모리 비용에 영향을 주는지 조사. 수를 줄이면 동작 품질이 달라질 수 있음 | Unity Sprite animation memory / 같은 동작과 대상 수에서 메모리와 표시 품질 비교 |
| 2D 뼈대 변형 | 동시에 보이는 대상과 메시 정점, 변형 처리의 비용 조사. 단순화는 관절 품질에 영향 가능 | Unity 2D Animation Sprite Skin profiling / 같은 동작에서 CPU와 변형 품질 비교 |

- Sprite Atlas와 렌더링 최적화는 [Sprite 규칙](<../Graphics/Sprite Convention.md>), Texture 메모리 설정은 [Texture 규칙](<../Graphics/Texture Convention.md>)을 참조한다.
- 프레임 순서, 반복 경계, 위치 흔들림, 관절 변형과 필요한 이벤트를 확인하도록 안내한다. 파일 설정 확인을 실제 재생 확인으로 보고하지 않는다.
