# 사운드 공통 컨벤션

## 목적과 적용 범위

기존 음원을 Unity에서 활용할 때 요구를 확인하고 재생 구성과 설정을 제안하는 기준이다.
효과음, UI 음, 배경음과 환경음을 다루며 사운드 생성은 포함하지 않는다.
개별 음원의 검색과 후보 선정, 다운로드는 사용자 작업이다.

## 용도와 분위기 확인

- 기존 게임 구성, 코드와 사용자 제공 자료에서 확인되는 내용은 먼저 조사하고 남은 사항만 질문한다.
- 언제, 어디서, 어떤 느낌으로 들려야 하는지 확인한다. 사용자가 음향 용어를 알아야 하는 것으로 요구하지 않는다.
- 발사, 피격, UI 입력, 배경음 등 사용 상황과 단발, 연속, 반복 여부를 구분한다.
- 현실적, 과장된, 가벼운 전자음 같은 인상과 길이, 여운, 공간감, 다른 소리와의 관계를 필요한 범위에서 확인한다.
- 표현이 어려우면 참고 음원이나 영상 구간을 받아 어떤 특징을 원하는지 질문할 수 있다. 참고 자료 제공은 필수 조건으로 강제하지 않는다.
- 답변을 바탕으로 방향을 요약하고 확인받는다. 이미 정한 내용을 반복 질문하지 않는다.
- 실제로 듣거나 분석하지 못한 자료의 소리와 분위기를 확인했다고 표현하지 않는다.

### 질문과 방향 확인 예시

“총 발사음을 넣어줘”라는 요청에는 기존 무기 구성을 확인한 뒤 필요한 질문만 한다.

> 플레이어의 연사용 총에 넣는 소리인가요? 현실적인 총소리와 짧은 전자음 중 어느 쪽을 원하시나요? 긴 울림이 남아도 될까요?

답변 후의 정리 예시는 다음과 같다.

> 짧고 날카로운 SF 연사음에 약간의 저음을 원하고, 긴 울림은 피하는 방향입니다. 이 조건으로 검색할 사이트와 키워드를 안내하겠습니다.

## 사이트와 검색어 안내

- 에이전트는 관련 사이트와 해당 사이트에서 사용할 검색어 및 필터까지만 안내한다. 개별 음원을 대신 찾거나 후보 목록을 선정하지 않는다.
- 용도와 분위기에 맞는 검색어를 제안하고 뜻을 설명한다. 예를 들어 `sci-fi gunshot`, `short`, `heavy`, `dry`는 각각 SF 발사음, 짧은 길이, 묵직한 느낌, 울림이 적은 소리를 찾는 표현으로 안내할 수 있다.
- 사용자가 직접 검색하고 듣고 선택하며 다운로드한다. 요청하지 않은 계정 생성이나 다운로드를 수행하지 않는다.
- 별도 요청이 없으면 무료 CC0 음원을 찾을 수 있는 조건으로 안내한다. 사이트의 전체 음원이 무료 또는 CC0이라고 가정하지 않는다.
- 사이트를 구체적으로 추천할 때 최신 공식 이용 안내와 검색 기능을 확인해 라이선스 필터 및 개별 페이지에서 확인할 위치를 설명한다. 필터가 없으면 없는 것으로 안내한다.
- CC0 필터 사용만으로 모든 권리와 사용 조건 확인을 끝냈다고 단정하지 않는다. 사용자가 선택한 파일의 표시와 출처를 확인하는 방법을 안내한다.
- 사용자가 제공한 음원도 사용 조건을 자동 확보한 것으로 간주하지 않는다. 프로젝트 사용에 영향을 주는 불명확한 사항은 확인한다.

## 기존 구성과 작업 역할

- [프로젝트 값](<../../Project Values.md>)과 실제 환경, 기존 음원과 AudioSource, AudioMixer, AudioListener, 코드 및 애니메이션 이벤트 연결을 확인한다.
- 문서와 실제 환경의 차이는 [환경 규칙](<../Work/Environment Convention.md>)에 따라 보고한다.
- 기존 음원, AudioSource, Mixer와 코드 연결은 수정 지시 없이 변경하지 않는다. 공유 설정의 사용처와 영향을 확인한다.
- 대상 파일과 설정, 생성할 구성, 영향과 검증 방법을 브리핑하고 [승인 범위](<../Safety/Approval Convention.md>)를 따른다.

| 작업 | 기본 역할 |
|---|---|
| 사이트와 검색어 안내 | 에이전트가 용도와 조건에 맞춰 설명 |
| 음원 검색, 선택과 다운로드 | 사용자 직접 수행 |
| 프로젝트에 음원 추가 | 사용자 직접 수행, 에이전트가 위치와 방법 안내 |
| 기존 오디오 구성과 코드 조사 | 에이전트가 파일과 사용 가능한 도구로 확인 |
| 기본 재생 컴포넌트와 참조, 호출 코드 연결 | 에이전트가 승인된 범위에서 수행 |
| 임포트 설정 | 에이전트가 값과 이유를 추천하고 사용자 적용 안내 |
| Mixer 사용 시점과 설정 방법 | 에이전트가 요구에 맞게 설명하고 사용자 설정 안내 |
| 듣기 품질과 음량, 음색, 감쇠의 세밀한 조정 | 사용자 직접 수행, 에이전트가 조정 방법 안내 |

- 파일 제공을 전체 사운드 시스템 구축 승인으로 확대하지 않는다. 기본 연결 후 결과를 보고하고 다음 요청을 기다린다.
- 이미 승인한 동일 범위는 재승인을 요구하지 않는다. 새 Manager나 구조를 사운드 작업이라는 이유만으로 도입하지 않는다.
- 컴포넌트 배치와 이름은 [계층구조](<../Work/Hierarchy Convention.md>), 파일 위치는 [구조 규칙](<../Work/Structure Convention.md>)을 따른다.
- 사용자 직접 설정을 실제 적용한 것으로 보고하지 않는다. 도구 지원 여부와 파일 분석, 에디터 실행 결과를 구분한다.

## 용도별 AudioSource 설정 추천

AudioSource는 오브젝트에서 음원을 재생하는 컴포넌트다. 모든 음원에 같은 설정을 강제하지 않고 기존 구성과 실제 사용 방안에 맞춰 추천한다.

| 설정 또는 선택 | 설명과 추천 기준 |
|---|---|
| Play On Awake | 활성화 시 자동 재생할지 결정. 발사나 버튼 입력에 연결하는 소리와 자동 시작 배경음을 구분 |
| Loop | 반복 여부. 반복음의 시작과 종료 조건, 원본의 반복 경계도 확인 |
| Volume | 기본 음량. 원본 음량과 Mixer, 겹치는 소리를 고려해 초기값과 조정 방법 제안 |
| Pitch | 재생 높낮이와 속도에 영향을 주는 값. 변화가 필요한 이유와 허용 범위를 설명 |
| Spatial Blend | 위치에 따른 공간 효과의 적용 정도. 0은 2D, 1은 완전한 3D이며 장르의 2D/3D 구분과 별개로 선택 |
| Volume Rolloff와 거리 설정 | 거리별 감쇠. 청취 위치와 월드 크기, 소리가 필요한 범위를 근거로 추천 |
| Output | 연결할 Mixer 그룹. 기존 그룹 구성과 음량 제어 요구 확인 |
| Doppler Level | 상대 이동에 따른 높낮이 변화. 의도한 연출인지 확인 |
| Priority | 동시에 많은 소리가 재생될 때 중요도 검토. 모든 소리를 최고 우선순위로 지정하지 않음 |
| 재생 호출 방식 | 겹쳐 재생, 기존 소리 교체, 반복 시작과 종료 요구를 근거로 API와 컴포넌트 구성 비교 |

- 추천값은 초기 청취용으로 제안하며 프로젝트 전체의 정답으로 고정하지 않는다. 수치와 선택 이유, 예상 변화와 확인 방법을 함께 설명한다.
- 기존 설정을 먼저 확인하고 요청과 관계없는 항목까지 일괄 변경하지 않는다.
- Max Distance를 모든 감쇠 방식에서 무조건 소리가 꺼지는 거리로 설명하지 않는다. 실제 감쇠 방식과 청취 결과를 확인한다.
- AudioListener의 위치와 플레이어 또는 카메라의 관계를 확인한다. 거리감 문제를 AudioSource 값만의 문제로 단정하지 않는다.
- 예를 들어 UI 클릭음은 위치와 무관한 2D 재생을, 월드의 적 발사음은 거리감을 활용하는 방식을 검토한다. 최종 선택은 실제 요구에 따른다.

## AudioMixer 사용 시점과 설정 안내

AudioMixer는 여러 소리를 그룹으로 묶어 음량과 효과 등을 제어하는 기능이다. AudioSource별 조절로 충분한 경우와 비교해 도입 이유와 비용을 설명한다.

- 배경음과 효과음의 그룹별 음량, 옵션 메뉴 연동, 여러 소리의 일괄 효과나 상태별 전환이 필요할 때 검토한다. 모든 작업에 필수로 만들지 않는다.
- 기존 Mixer와 그룹이 있으면 사용처와 요구를 확인해 활용안을 제안한다. 정리 목적으로 기존 그룹과 파라미터 이름을 임의 변경하지 않는다.
- 실제 버전에 맞는 메뉴와 항목 이름으로 아래 순서를 안내한다.

1. Mixer 생성과 기존 Mixer 활용 중 적합한 방법 선택 → 확인: 저장 위치와 사용처
2. 필요한 그룹 구성 → 확인: Master, BGM, SFX 등 제안한 역할과 계층
3. AudioSource의 Output 연결 → 확인: 의도한 그룹으로 전달되는지
4. 필요 시 파라미터 노출과 이름 지정 → 확인: 기존 코드와 이름 충돌
5. 승인한 코드 연동 → 확인: 값 범위와 적용 시점, 기존 제어와 충돌
6. 사용자 청취 조정 → 확인: 그룹 균형과 실제 게임 상황의 결과

- 그룹 이름은 예시이며 고정 생성 목록이 아니다. 필요한 그룹만 제안한다.
- 음량의 dB 표시와 사용자 조절값의 의미를 설명하고 단순히 같은 숫자를 전달하면 된다고 가정하지 않는다. 음소거와 값 변환의 처리도 요구에 맞춰 안내한다.
- Snapshot을 사용하면 저장된 믹싱 상태와 전환의 역할을 설명한다. 노출 파라미터를 코드로 제어하는 경우 Snapshot과 제어 책임을 확인한다.
- 음량 균형과 효과의 세밀한 설정은 사용자가 직접 듣고 조정한다. 에이전트는 값의 의미, 예상 변화, 조작과 청취 테스트 방법을 안내한다.
- 기존 Mixer는 수정 지시 없이 변경하지 않는다. 직접 설정까지 요청받으면 도구 지원과 실제 변경 대상, 승인 범위를 먼저 확인한다.

## 재생과 중단 정책

- 발사, 피격, 버튼 입력, Scene 진입 등 어떤 동작에 재생을 연결할지 정한다.
- 연속 요청을 겹쳐 재생할지, 이전 소리를 끊을지, 무시할지 용도에 맞춰 제안한다. 모든 효과음에 같은 정책을 적용하지 않는다.
- 반복음의 시작과 끝을 정하고 정상 종료와 강제 중단을 구분한다.
- 배경음 등을 즉시 교체할지, 서서히 줄이거나 겹쳐 전환할지 대안과 추가 구성을 설명하고 선택받는다.
- 비활성화, 파괴, Scene 전환, 풀 반환 시 소리를 유지할지 중단할지, 어느 객체가 재생을 소유할지 확인한다.
- 게임 일시정지 중 함께 멈출 소리와 계속 재생할 소리를 구분하고, 페이드 등의 시간 기준도 확인한다.
- 코드와 애니메이션 이벤트가 같은 소리를 의도치 않게 중복 호출하지 않는지 확인한다.
- 이벤트의 수명과 참조 정리는 [이벤트 규칙](<../Code/Event Convention.md>)과 [참조 관리](<../Code/Reference Convention.md>), 시간에 따른 전환과 취소 구현은 [비동기 규칙](<../Code/Async Convention.md>)을 따른다.

예를 들어 연사음은 각 발사음을 겹쳐 재생하는 방법과 반복음을 시작한 뒤 발사를 멈추면 종료하는 방법을 비교한다. 발사 코드와 요구에 맞춰 선택하고, 발사 중단과 무기 교체 및 비활성화 시 정리까지 안내한다.

## 임포트 설정과 최적화

- 음원 길이, 재생 빈도, 동시 재생 수, 플랫폼과 용도에 맞춰 임포트 설정의 의미와 추천 이유를 설명한다.
- Load Type, 압축 형식과 품질, 채널 구성 등 실제 문제에 관련된 항목만 검토한다. 모든 짧은 효과음이나 배경음에 하나의 설정을 고정하지 않는다.
- 로딩 시 압축 해제, 재생 중 압축 해제, 스트리밍 등 방식의 메모리와 CPU, 저장장치 접근 비용을 비교할 때 현재 버전과 대상 환경의 공식 설명을 확인한다.
- 최적화는 실제 문제나 성능 요구가 있을 때 원인을 조사하며, 공통 절차는 [성능 규칙](<../Safety/Performance Convention.md>)을 따른다.
- 같은 Scene과 음원, 재생 수, Mixer 효과, 청취 위치 조건에서 전후 비교한다. CPU와 메모리뿐 아니라 시작 지연, 끊김과 듣기 품질도 확인한다.
- 동시 소리 수와 재생 소유권이 문제라면 기존 재사용 구성을 먼저 확인한다. 풀링이나 새 관리 구조를 측정 없이 도입하지 않는다.
- 측정하지 않은 성능 향상은 미확인으로 보고하고, 기존 음원과 설정을 최적화 이유로 임의 변경하지 않는다.

## 검증과 결과 보고

검증의 공통 절차는 [테스트 규칙](<../Safety/Testing Convention.md>)을 따른다. 아래에서 변경한 기능과 관련된 항목을 선택한다.

| 확인 대상 | 확인 내용과 역할 |
|---|---|
| 기본 연결 | 에이전트가 참조, 재생 호출과 종료 경로를 확인. 실제 실행 여부를 구분 |
| 정상 재생과 중복 | 사용자에게 정상 입력과 연속 요청의 테스트 순서 및 예상 결과 안내 |
| 반복과 전환 | 사용자가 반복 경계의 끊김, 페이드와 교체 결과 청취 |
| 공간감 | 필요한 경우 사용자가 거리와 방향을 바꿔 감쇠와 청취 위치 확인 |
| 음량 균형 | 사용자가 배경음, 효과음과 동시 재생 상황을 듣고 조정 |
| 수명과 정지 | 비활성화, 재사용, Scene 전환, 일시정지와 재개 시 합의한 정책 확인 |
| 성능 | 관련 문제의 전후 측정과 청취 품질 확인. 미측정 효과는 미검증 |

- 직접 확인한 파일과 코드, 실제 실행 결과, 사용자가 전달한 청취 결과와 미검증 항목을 구분한다.
- 사용자에게 조작 순서와 예상 결과를 제공한다. 단순히 “들어보고 확인”이라고만 안내하지 않는다.
- 반복 환경음은 반복 경계에서 끊기거나 튀는지, 연사음은 연속 입력과 중단 후 불필요한 소리가 남는지 확인하도록 안내한다.
- 보고는 변경한 파일과 설정, 추천값의 이유, 수행한 확인, 사용자 조정 항목과 남은 문제를 중심으로 작성한다.
