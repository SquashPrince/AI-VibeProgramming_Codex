# 성능 컨벤션

> 상태: 공통 운영 기준.
> 대상: Unity/C# 기반 AI 보조 개발. 기존 승인 규칙과 사용자 확정 사항을 유지한다.

## 목적
정확성과 가독성을 유지하면서 확인된 병목을 개선한다.

## 규칙
- 핵심 기능이 동작한 뒤 최적화한다. 성능 요구나 실제 병목이 있다면 우선순위를 조정한다.
- 추측만으로 패턴·자료구조·패키지를 교체하지 않는다.
- 자주 실행되는 경로의 반복 조회·불필요한 생성과 할당·중복 계산을 점검한다.
- 캐싱·풀링은 수명·초기화와 반환 책임·복잡도 증가를 함께 평가한다.
- Update 필요성은 동작을 기준으로 판단한다. 이벤트 전환 자체를 성능 개선으로 단정하지 않는다.

## 측정 절차
1. 대상 기기·빌드·재현 Scene·데이터 크기를 기록한다.
2. CPU 시간·메모리·할당 등 문제와 관련된 값을 측정한다.
3. 같은 조건에서 변경 전후를 비교하고 기능 회귀를 확인한다.
4. 결과와 비용을 보고한다. 측정하지 못했다면 효과는 미확인으로 적는다.

## 승인
작업 범위 밖 최적화와 새 구조 도입은 제안 후 승인을 받고 적용한다.

## 프로젝트별 값
확정 값은 [프로젝트 값](<../../Project Values.md>), 미확정 값은 [프로젝트 설정](<../../Project Configuration.md>)을 따른다. 미확정 값의 확인 · 등록은 `project-setup` 스킬로 수행한다.
