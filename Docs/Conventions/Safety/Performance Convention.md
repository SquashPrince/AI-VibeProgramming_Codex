# 성능 컨벤션

> 상태: 공통 운영 기준.
> 대상: Unity/C# 기반 AI 보조 개발. 기존 승인 규칙과 사용자 확정 사항을 유지한다.

## 목적
정확성과 가독성을 유지하면서 확인된 병목을 개선한다.

## 규칙
- 핵심 기능이 동작한 뒤 최적화한다. 성능 요구나 실제 병목이 있다면 우선순위를 조정한다.
- 추측만으로 패턴·자료구조·패키지를 교체하지 않는다.
- 자주 실행되는 경로의 반복 조회·불필요한 생성과 할당·중복 계산을 점검한다.
- 캐싱·풀링은 수명·초기화와 반환 책임·복잡도 증가를 함께 평가한다.
- Update 필요성은 동작을 기준으로 판단한다. 이벤트 전환 자체를 성능 개선으로 단정하지 않는다.

## 측정 절차
1. 대상 기기·빌드·재현 Scene·데이터 크기를 기록한다.
2. CPU 시간·메모리·할당 등 문제와 관련된 값을 측정한다.
3. 같은 조건에서 변경 전후를 비교하고 기능 회귀를 확인한다.
4. 결과와 비용을 보고한다. 측정하지 못했다면 효과는 미확인으로 적는다.

## 최적화 설명과 대안 검토

- 관련 기법의 한글·영문 이름, 개념·목적, 적용 조건, 장단점·추가 비용, 현재 프로젝트에 제안하는 이유와 테스트 방법을 설명한다.
- 사용자가 다른 방법도 찾아볼 수 있도록 실제 검색에 쓸 키워드를 제공한다. 관련성 높은 기법을 중심으로 설명하고 매번 모든 기법을 나열하지 않는다.
- 사용자가 찾은 자료·대안도 프로젝트 버전·지원 조건·장단점과 근거를 확인해 비교하고 필요하면 권장안을 조정한다.
- 공식적으로 확인된 동작과 프로젝트 적용 가정, 실제 측정 결과를 구분한다. 검색 자료의 존재만으로 적합성이나 성능 향상을 단정하지 않는다.
- 공통 절차는 이 문서에서 관리한다. 분야별 개념·조건·검색어·테스트 방법은 해당 규칙 문서에 두고 중복 설명은 참조로 연결한다. 그래픽 분야는 [그래픽 공통 컨벤션](<../Graphics/Common Convention.md>)에서 진입한다.

## 그래픽 사용자 작업과 측정

- 그래픽 에디터 작업의 수행 주체는 해당 분야 문서의 합의를 따른다. 사전에는 현황 검토·변경안·예상 효과와 위험을 설명하며 검증 완료로 보고하지 않는다.
- 사용자 직접 변경 작업은 사용자가 설정을 바꾼 후 실제 적용 환경에서 테스트한다. 에이전트는 변경 전후 비교 조건, 확인 도구·조작 방법과 관련 지표를 안내한다.
- 비교 조건에는 대상 기기·빌드 여부·Scene·카메라·해상도·대상 수 등 결과에 영향을 주는 항목을 필요한 범위에서 포함한다.
- 결과가 아직 없으면 효과는 미검증으로 남긴다. 사용자 결과를 바탕으로 화질·기능·성능과 비용을 함께 판단하고 유지·조정·복귀안을 검토한다.
- 정적 분석·컴파일·실제 표시·성능 측정을 구분한다. 이 절차가 에이전트가 승인 범위의 코드·파일·문서 검사를 수행하는 것을 금지하는 의미는 아니다.

## 승인

작업 범위 밖 최적화와 새 구조 도입은 제안 후 승인을 받고 적용한다.

## 프로젝트별 값
확정 값은 [프로젝트 값](<../../Project Values.md>), 미확정 값은 [프로젝트 설정](<../../Project Configuration.md>)을 따른다. 미확정 값의 확인 · 등록은 `project-setup` 스킬로 수행한다.
