# 승인 범위 컨벤션

> 상태: 공통 운영 기준. <br>
> 대상: Unity/C# 기반 AI 보조 개발. 기존 승인 규칙과 사용자 확정 사항을 유지한다.

## 목적
최초 승인으로 가능한 작업과 추가 승인이 필요한 작업을 구분한다.

## 계획에 포함할 내용
작업 목적·완료 조건, 수정/신규/삭제 파일, 예상 영향, 검증 방법을 제시한다.

## 최초 승인 범위
- 승인된 파일·기능 안에서 계획한 구현과 검증을 수행한다.
- 승인된 동작을 충족하기 위한 수정도 파일·영향 범위가 그대로라면 이어서 수행한다.
- 사용자가 사전에 확인·승인한 Manager·Interface·추상 클래스는 승인 범위 안에서 생성·구현하고, 완료 후 역할과 사용처를 보고한다.

## 추가 승인 대상
아래 작업은 대상과 변경 이유를 명시해 **사전 승인**을 받는다.

- 승인 목록 밖 파일 생성·변경·삭제 또는 요구 동작·공개 계약·데이터 구조 변경
- 구현 중 추가로 필요해진 미승인 Manager·Interface·추상 클래스 (생성·구현 전에 승인)
- `Assets/**/*.unity`, `Assets/**/*.prefab`, `**/*.meta`, `Packages/**`, `ProjectSettings/**`의 생성·변경·삭제 (각 파일별로 승인)
- 외부 패키지 설치, 폴더 구조 변경, 대량 파일 이동/이름 변경, 씬/프리팹 재저장

## 금지 규칙
- 컴파일 오류를 숨기기 위한 주석 처리, 경고 무시, 테스트 결과 허위 보고를 금지한다.
- 관련 없는 파일을 임의로 변경하거나 기능 요구를 임의로 확정하지 않는다. 작은 단위 작업을 같은 작업·PR에 포함할 때는 대상 파일과 영향을 먼저 보고하고 승인을 받는다.
- `.meta`는 에이전트가 미리 생성하지 않고 Unity 임포트로 생성되게 한다. 구현상 직접 생성·수정이 필요한 경우에만 이유·대상 파일·영향을 설명하고 사전 승인을 받아 수행한다. 수동 삭제·임의 수정은 금지한다.
- Git 변경 작업의 금지와 수행 주체는 [AI 에이전트 공통 지침](<../../Codex/AgentCommonRules.md>)의 `Git 작업 제한`을 따른다. 추가 승인으로 금지가 해제되지는 않는다.

## 처리
- 추가 변경의 이유·대상 파일·영향·검증 방법을 제시하고 승인을 기다린다.
- 독립적으로 진행 가능한 기존 승인 작업은 계속할 수 있다.
- 이 문서는 행동 기준이며 실제 파일·서비스 접근 권한을 부여하지 않는다.
