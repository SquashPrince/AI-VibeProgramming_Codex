# Github Commit 작성 규칙

> Github Commit을 작성할 때의 규칙.

> Commit 작성 양식은 [Commit 템플릿](<../Templates/Commit.md>)을 참고.

> 해당 문서는 제목, 각 섹션, 태그에 대한 작성 규칙을 정의한다.

## 0. 작성 절차

- AGENT는 메시지 형식과 포함할 변경 파일만 안내한다.
- 작업과 관계없는 파일이 변경 목록에 있으면 사용자에게 알린다.

## 1. 제목

- 제목은 `[태그] 대표 내용` 형식으로 작성
- 태그는 [Git 컨벤션](<../Conventions/GitHub/Git Convention.md>)의 Commit 종류를 따른다.
- 대표 내용은 구현한 내용중 핵심 내용 하나를 요약해 명사형으로 끝나도록 작성한다.
- 제목에는 괄호 `()` 를 사용하지 않는다.
- 예시 : 
    ```markdown
    [Feat] 플레이어 이동 구현
    ```

## 2. Commit 내용

- 핵심 작업을 포함한 대표적인 구현 내용을 최소 1개, 최대 3개 적는다.
- 제목에 적었던 핵심 내용은 필수가 아니며, 제목을 제외하고 다른 내용 3개로 적어도 된다.
- 하지 않은 작업이나 없던 작업을 갯수를 채우기 위하여 적지 않는다.
- 갯수를 채우기 위하여 하나의 작업을 여러개로 나누어 적지 않는다.
- 예시 :
    ```markdown
    - 플레이어 이동 구현
    - 플레이어 점프 구현 진행중
    ```
