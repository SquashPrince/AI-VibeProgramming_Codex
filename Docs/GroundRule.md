# Ground Rule

## 1. 최우선 원칙

1. **작동하는 작은 완성본이 우선**이다.  <br>
최적화·꾸미기·도구 제작은 핵심 루프가 동작한 뒤 혹은 사용자가 요구시 진행한다.
2. 주요 구현은 한 번에 하나의 명확한 기능 단위로 진행한다. 구현 범위가 커지면 작은 작업으로 분리한다. 승인된 작은 부수 수정은 영향과 검증을 구분해 같은 작업·PR에 포함할 수 있다.
3. 승인된 개발 명세를 기준으로 한다. 미확정 사양은 실험 가정으로 구분한다.
4. 사용자와 AI-AGENTS의 역할을 구분한다. <br>
AI-AGENTS는 제안·구현·검증 보조, 사용자는 승인·최종 확인 담당이다.

## 2. 작업 시작 전

- 작업 목표, 완료 조건, 영향받는 시스템을 한두 문단으로 정리한다.
- 관련 명세·컨벤션·기존 파일을 확인한다.
- 신규 파일 또는 Scene/Prefab/패키지 변경이 필요한지 검토한다.
- AI-AGENTS 작업은 `Docs/Codex/WorkflowRules.md`의 **브리핑 → 승인** 절차를 따른다.
- 개발·버그 수정·문서 변경은 작업 브랜치에서 진행한다. 브랜치 생성과 전환은 사용자가 직접 수행하며, 형식은 [Git 컨벤션](<Conventions/GitHub/Git Convention.md>)을 따른다.

## 3. 진행 중

- 요청된 범위 밖 기능은 추가하지 않는다.
- `.meta`, Scene, Prefab, ProjectSettings, Packages 등 보호 대상의 변경은 [승인 범위 컨벤션](<Conventions/Safety/Approval Convention.md>)을 따른다.
- 오류를 주석 처리해 숨기지 않는다. 원인을 확인하고 재현 조건을 남긴다.

## 4. 문서 간 역할

문서별 역할은 [문서 유지 컨벤션](<Conventions/Work/Documentation Convention.md>)의 `문서 역할`을 따른다.
