# 기술 문서 작성

> 이 스킬은 절차와 멘트 규격만 정의한다. 규칙의 원본은 아래 문서이며, 내용을 이 파일에 복사하지 않는다.
>
> 이 스킬은 Git 작업(브랜치 확인 · Commit 안내)을 하지 않는다.

## 참조 문서 (필요 섹션만 읽는다)

- 위치 · 작성 절차 · 보안 · 다이어그램 : `Docs/Conventions/Work/Technical Document Convention.md`
- 문서 양식 : `Docs/Templates/TechnicalDocument.md`

## 절차

1. 참조 문서를 읽는다.
2. `Docs/Technical/` 에 같은 기능의 문서가 있는지 확인한다. 있으면 갱신, 없으면 신규 작성으로 진행한다.
3. 대상 기능의 코드 · 작업 기록을 읽고, 양식 각 섹션에 들어갈 내용을 정리한다.
4. 사용자에게 기대 동작과 활용 목적, 주요 설계 선택의 이유를 하나씩 질문한다. 기록으로 확인할 수 없는 내용(참고 레퍼런스, 기존 방식, 필요하게 된 과정 등)도 질문한다. 이미 답한 내용은 다시 묻지 않는다.
5. 사용자 답변과 확인한 기록을 반영해 목차와 섹션별 핵심 한 줄을 보고하고 승인을 기다린다. (멘트 ①)
6. 승인되면 파일을 생성한다. 다이어그램은 `diagram` 스킬 절차를 따른다.
7. 작성한 본문이 원본 문서의 `보안` 규칙을 지키는지 확인한다.
8. 결과를 보고한다. (멘트 ②)
9. 수정 요청은 바뀌는 부분만 알리고 승인 후 고친다. 본문 전체를 다시 보여주지 않는다. (멘트 ③)

## 멘트 규격

① 목차 보고

```
## 기술 문서 목차 : <기술 이름>
- 저장 위치 : `Docs/Technical/<기능영역>/<문서명>.md` (<신규 / 갱신>)
- 근거 기록 : <참고한 코드 · Issue · PR · 대화>

1. 개요 : <핵심 한 줄>
2. 구성 요소 : <스크립트 이름 나열>
3. 동작 원리 : <핵심 한 줄> / 다이어그램 : <flowchart / SVG 제안 + 이유>
4. 구현 과정 : <핵심 한 줄> / 레퍼런스 : <있음 · 없음 · 질문 필요>
5. 기존 방식과 비교 : <기존 방식 비교 / 신규 기능의 필요 과정> - <핵심 한 줄>

확인 필요 : <사용자에게 물어볼 내용, 없으면 "없음">
이 목차로 작성할까요?
```

② 작성 후 보고

```
기술 문서 저장 : Docs/Technical/<기능영역>/<문서명>.md
- 보안 확인 : 코드 · 메서드 · 변수 이름 · 파일 경로 미포함
- 미정 · 미검증 항목 : <목록, 없으면 "없음">
```

③ 수정 안내

```
[기술 문서 수정] <문서명>
- <섹션> : <바뀌는 내용 한 줄>
수정할까요?
```
