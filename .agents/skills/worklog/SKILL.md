# 작업 일지 작성

> 이 스킬은 절차와 멘트 규격만 정의한다. 규칙의 원본은 아래 문서이며, 내용을 이 파일에 복사하지 않는다.
>
> 현재 날짜와 시간은 사용 가능한 시간 도구 또는 명령으로 확인한다. 작성 시간대 규칙은 원본을 따르되, 이 스킬 자체는 예약 실행 기능이 없으므로 사용자가 호출하거나 세션을 시작할 때 동작한다.

## 참조 문서 (필요 섹션만 읽는다)

- 작성 시기 · 누락 보완 · 기록 원칙 : `Docs/Conventions/Work/Documentation Convention.md` 의 `갱신 시점`
- 일지 양식 · 작성 위치 : `Docs/Templates/WorkLog.md`
- 작성자 폴더 이름 : `Docs/Project Values.md` 의 `작업 일지 작성자`
- 지난 날짜 질문 기록 : `.agents/state/worklog-review-state.json`

## 사용 시점

- 세션을 시작했을 때 : 이전 작업일의 일지 누락만 확인한다. 작업 기록이 없거나 이미 작성 여부를 질문한 날짜라면 알리지 않는다. (멘트 ①)
- 사용자가 업무를 마무리하거나 일지 작성을 요청할 때 : 오늘 일지를 작성한다. (멘트 ②)

## 절차

1. 참조 문서의 필요 섹션을 읽는다.
2. 현재 날짜와 시간을 명령으로 확인한다. 추측하지 않는다.
3. `Docs/DailyLogs/<작성자>/` 의 기존 일지와 작업 기록(Commit 이력, Issue · PR)을 비교해, 작업했지만 일지가 없는 날을 찾는다. 질문 기록에 있는 날짜는 다시 묻지 않는다.
4. 작업한 지난 날짜의 일지가 누락됐다면 작성할지 한 번만 질문하고 날짜를 질문 기록에 남긴다. 답변을 받으면 같은 기록에 답변을 남긴다. 사용자가 별도로 요청하기 전에는 같은 날짜를 다시 확인하거나 권유하지 않는다. 보완 내용은 확인 가능한 기록으로만 채운다.
5. 오늘 대화와 작업 기록에서 양식의 각 항목을 채운다. 해당 없는 항목은 `없음` 으로 적는다.
6. 초안을 사용자에게 보여주고 승인을 받는다. 기록에서 확인하지 못하고 사용자 답변으로 채운 부분은 따로 표시한다.
7. 승인 후 파일을 생성하고 경로를 보고한다. (멘트 ③)
8. 이미 작성된 일지는 수정하지 않는다. 작성 후 추가 작업은 다음 날 작성하는 일지에 포함한다.

## 멘트 규격

① 누락 확인

```
[작업 일지] 이전 작업일의 일지가 없습니다.
- 누락 날짜 : YYYY-MM-DD, ...
- 근거 : <Commit · Issue · PR 기록>
먼저 보완할까요?
```

② 작성 전 안내

```
## 작업 일지 초안 : YYYY-MM-DD
- 저장 위치 : `Docs/DailyLogs/<작성자>/YYYY-MM-DD.md`
- 근거 기록 : <참고한 Commit · Issue · PR · 대화>

(양식에 맞춘 본문)

이 내용으로 저장할까요?
```

③ 작성 후 보고

```
작업 일지 저장 : Docs/DailyLogs/<작성자>/YYYY-MM-DD.md
다음 작업 : <일지의 `다음 작업` 항목 요약>
```
