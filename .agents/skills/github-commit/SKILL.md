# Commit 작성 안내

> 이 스킬은 절차와 멘트 규격만 정의한다. 규칙의 원본은 아래 문서이며, 내용을 이 파일에 복사하지 않는다.
>
> AGENT 는 Commit · Push 를 직접 실행하지 않는다. 메시지 초안과 포함할 파일만 안내하고, 실행은 사용자가 한다.

## 참조 문서 (필요 섹션만 읽는다)

- 업무 흐름 : `Docs/Codex/WorkflowRules.md` 의 `7. Commit / Push`
- 제목 · 내용 · 태그 규칙 : `Docs/Documentation/Github Commit Rule.md`
- 메시지 양식 : `Docs/Templates/Commit.md`
- 변경 단위 : `Docs/Conventions/GitHub/Git Convention.md` 의 `3. Commit과 PR`, `변경 단위와 리뷰`

## Commit 권유 시점

아래에 해당하면 작업이 오래 쌓이지 않도록 Commit 을 권유한다. (멘트 ①)

- 브리핑의 작업 순서 중 한 단계가 끝나 `확인` 항목을 통과했을 때
- 사용자 검수가 승인됐을 때
- 서로 관계없는 변경이 함께 쌓이기 시작할 때

## 절차

1. 참조 문서의 필요 섹션을 읽는다.
2. 현재 브랜치와 변경 파일 목록을 확인한다. `main`, `main-dev` 브랜치이면 중단을 요청한다.
3. 작업과 관계없는 파일을 찾아 제외 권장 대상으로 분류한다.
4. 양식에 맞춰 메시지 초안을 작성하고, 포함 파일과 함께 안내한다. (멘트 ②)
5. 사용자가 Commit 했다고 알리면 최근 Commit 을 확인하고 보고한다. (멘트 ③)

## 멘트 규격

① Commit 권유

```
[Commit] 커밋할 시점입니다.
- 이유 : <단계 완료 / 검수 승인 / 무관한 변경 누적>
- 변경 파일 : N개
메시지 초안을 작성할까요?
```

② Commit 전 안내

```
## Commit 초안
- 브랜치 : <브랜치>
- 포함 파일 : <경로 목록>
- 제외 권장 : <작업과 무관한 파일> (없으면 생략)

[태그] 대표 내용
- 내용 (1~3개)

이 내용으로 직접 커밋해 주세요.
```

③ Commit 후 확인

```
커밋 확인 : <해시 7자리> [태그] 대표 내용
다음 단계 : <다음 작업 단계 / Push 후 PR>
```
